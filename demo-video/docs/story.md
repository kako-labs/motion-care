# 이야기 영상 (MotionCareStory)

출발 전부터 다음 출발까지 실제 순서대로 따라가는 약 3분 10초 영상입니다. 3분 영상(`MotionCare3Min`, `docs/3min.md`)을 다시 만든 것입니다.

- **결과:** `out/motioncare-story.mp4` (1920x1080, 30fps, 알림음만). 영상과 녹화본(`public/rec/`)은 Git에 넣지 않습니다.
- **편집 파일:**
  - `src/story/scenes.ts`: 장면 한 줄이 하나입니다(녹화본의 어느 구간, 자막, 강조). 자막은 장면의 `caps`에 있습니다.
  - `src/story/Story.tsx`: 화면 구성과 타이틀·마무리 문구가 있습니다.

## 왜 다시 만들었나

이전 3분 영상에 대한 팀 피드백은 이랬습니다.

> 너무 확대한다거나, 초반에 뭔가 반짝반짝하면서 갑자기 지나가는 기능이 있다거나. 자연스러운 기능 소개와 진행 순서. 모든 게 다 부족했던 것 같다.

이전 영상을 프레임으로 보니 다음과 같았습니다.
- 장면마다 움직이는 확대가 있었고, 확대할 때 테두리가 빛났습니다.
- 앱 장면을 1.1~2.4배속, 주행 장면을 최대 4.7배속으로 돌렸습니다. 그래서 기능이 4~6초씩 지나갔습니다.

### 방향을 정한 근거

같은 상황 설명만 준 AI 페르소나 세 개에게 따로 의견을 받았습니다(2026-11-12). 실제 전문가가 아닙니다.
- 페르소나: 시연 영상 감독, 차량 HMI·UX 전문가, 공모전 심사위원
- 상황 설명: 공모전, 앱 기능, 촬영 소스, 제약, 위 피드백

**세 의견이 같았던 것**
- 한 운행을 P → D → P → 다음 출발 순서로 따라가고, 주행을 가장 길게 둡니다.
- 기능 몽타주나 반짝이는 타이틀 없이 시작합니다.
- 전체 화면을 고정하고, 왼쪽 속도·기어를 자르지 않습니다.
- 원인과 결과(기어, 탭, 카드)는 1배속으로 둡니다. 기다리는 구간은 컷하고 "n분 뒤"를 표시합니다.
- 자막은 한 번에 한 문장으로 쓰고, 장 이름을 늘 띄웁니다.
- 콘솔은 한 번만 보여 주고, 끝에 녹화 방식과 진단 아님을 밝힙니다.

**사용자·팀 결정**

| 항목 | 결정 |
| --- | --- |
| 확대 | 글자가 작은 계산 방법 장면 하나에만 고정 1.5배. 페르소나 셋 중 둘이 1.5배 이하를 허용함 |
| 내레이션(TTS)·배경음악 | 넣지 않음. 소리는 카드 알림음뿐. 비교용으로 내레이션 버전을 따로 만듦(아래 "내레이션 버전") |
| 공기 카드 | 뺌. 촬영 날 서울 대기질이 '보통'이라 카드가 뜰 조건이 아니었고, 15분 간격 규칙 때문에 패턴 카드와 같은 운행에 띄울 수 없음 |
| 타이틀 | 앱 아이콘, 이름, 한 줄 소개("동승자의 멀미를 줄이도록 운전 습관을 돕는 Pleos 차량용 앱")만 약 3.5초 |
| 첫 문장 | 뺌. 처음에는 "운전하는 사람은 괜찮은데, 뒷자리 아이는 멀미를 합니다"를 타이틀 앞에 띄웠음. AI가 쓴 문장 같다는 의견에 Codex 페르소나 셋(카피라이터, UX 라이터, 영상 작가)의 대안을 받아 봤으나, 문장 없이 가기로 함 |
| 자막 문장 | 팀원이 다듬은 설명형 문장 하나씩(작은 줄 없음). 사실과 다른 곳만 고침(아래) |
| 감속 이름 | 첫 감속 장면만 앱 화면과 같은 '정차 직전 큰 감속'으로 쓰고, 나머지는 '급정거' |
| 기록·다음 출발 장면 | 시연용 기록으로 찍음. 테스트 주행 운행은 40km/h를 오르내리는 단순한 그래프라, 시연용으로 만든 실제 같은 운행을 두고 그걸 보여 줄 이유가 없음 |

**팀원 자막에서 고친 곳**
- **차 안 환경:** "그 순간의"를 "이 운행의"로 고쳤습니다. 환경 값은 감속 순간이 아니라 운행 시작, 1시간마다, 종료 때 저장됩니다.
- **기록 첫 장면:** "방금 끝난 운행은 목록 맨 위에"를 "운행이 끝날 때마다 기록이 쌓입니다"로 고쳤습니다. 기록을 시연용 데이터로 바꿨기 때문입니다.
- **다음 출발:** "오늘 운행이 반영된 조언"을 "쌓인 기록으로 고른 조언"으로 고쳤습니다. 같은 이유입니다.

## 구성 (3:10)

| 시간 | 장 | 장면 | 녹화본 |
| --- | --- | --- | --- |
| 0:00~0:03 | 타이틀 | 남색 바탕에 앱 아이콘·이름·한 줄 소개. 빛 효과 없이 나타나고 사라짐 | |
| 0:03~0:27 | 출발 전 | 내비가 앞에 있는 주차 상태에서 하단 바로 앱을 엶. 홈의 출발 조언("1.7회에서 0.5회로"), 함께 타는 사람, 좌석 | 본 테이크 |
| 0:27~1:19 | 주행 | 기어 D로 기록 시작(콘솔 작은 창 5초), 내비, 정차 직전 큰 감속 3번, 내비 위 카드와 알림음, 카드가 저절로 사라짐 | 본 테이크 |
| 1:19~1:51 | 도착 | P, 3분 뒤 자동 종료, 서아의 이동 평가(보호자가 대신, 별 3개, 출발·정차). 저장하면 바로 다음 사람 화면으로 넘어가서 저장 직전에 끊음 | 본 테이크 |
| 1:51~2:40 | 기록 | 기록 목록, 서아만 보기, 11/5 16:39 운행(지영 운전, 12분, 정차 직전 큰 감속 5번)의 그래프·세 번째 감속·차 안 환경·서아 4/5와 주행 중 안내 1번, 운전자 프로필(−68%)과 3주 흐름 | 기록 테이크 |
| 2:40~3:02 | 다음 출발 | 홈 조언("1.7회에서 0.5회로"), 왜 이 조언인지, 계산 방법(1.5배 확대) | 기록 테이크 |
| 3:02~3:10 | 마무리 | 앱 아이콘과 이름, 기록 → 카드 → 평가 → 조언, 영상에 나온 차량 기능, 녹화 방식과 진단 아님 | |

**화면 규칙**
- **화면:** Pleos 화면(2560x1440)을 1568x882로 같은 자리에 둡니다. 아래 자막 띠에는 장 이름과 문장 하나가 들어갑니다.
- **강조:** 주변을 조금 어둡게 하고 얇은 테두리를 그립니다. 빛 번짐과 깜빡임은 없습니다. 속도 표시와 카드에는 테두리만 씁니다.
- **누른 위치:** 녹화 스크립트가 누른 위치와 시각을 적어 두고 옅은 원으로 그립니다. 에뮬레이터의 시스템 터치 표시(`show_touches`)는 화면에 나오지 않았습니다.
- **소리:** 카드 알림음 한 번뿐입니다. 녹화한 에뮬레이터 소리를 26dB 키우고 클리핑을 막았습니다.
- **속도:** 모든 장면이 1배속입니다. 건너뛴 구간은 "1분 뒤", "3분 뒤"로 표시합니다.

## 녹화 (tools/rec)

AVD `pleos`(emulator-5600)만 씁니다. 실행 조건은 `docs/3min.md`의 녹화 절과 같습니다(오디오, gRPC 8590, Virtual Console 8796).

1. **기록을 맞춥니다.** 저장소 루트에서 `python3 docs/pleos-emulator/tools/film_takes.py restore`를 실행해 시연용 20건으로 시작합니다.
2. **본 테이크:** `python3 story_take.py <폴더>` (약 13분)
   - 순서: 내비 앞 → 하단 바로 앱 → 좌석 → 기어 D → 하단 바로 내비 → 40km/h, 약 75초 간격으로 세게 정차 3번 → 카드 → 3분 주행 → P → 3분 뒤 자동 종료 → 이동 평가 → (이후 장면은 쓰지 않음)
   - 운행 하나와 평가 하나가 기록에 더해집니다.
3. **기록을 되돌립니다:** `film_takes.py restore`
4. **기록 테이크:** 앱 홈을 앞에 두고 `python3 history_take.py <폴더>` (약 2분)
   - 순서: 기록 탭 → 서아 → 아래로 → 11/5 16:39 운행 → 세 번째 감속 → 아래로 두 번 → 프로필 → 아래로 → 홈 → 왜 이 조언인가요 → 계산 방법
   - 아무것도 저장하지 않습니다.
5. **맞춥니다:** 에뮬레이터 시계 − 호스트 시계(ms)를 재서 넘깁니다(11/12 측정 −1046~−1052).
   - 명령: `python3 tools/rec/prep_story.py <본 테이크> -1048 history=<기록 테이크>`
   - 결과: `public/rec/{story_pleos,story_console,history_pleos}.mp4`, `public/rec/story_audio.wav`, `src/data/{story,history}.json`
   - 알림음은 앱 로그(`GuidanceSound: started`) 시각에 맞춥니다(`docs/3min.md`의 시각 맞춤과 같음).
- **방금 운행을 보여 주려면:** `detail_take.py`는 본 테이크 직후, 되돌리기 전에 그 운행의 상세를 찍는 도구입니다. 지금 영상은 쓰지 않습니다.

## 내레이션 버전 (MotionCareStoryTts)

내레이션이 있는 것과 없는 것을 비교하려고 만든 버전입니다(11/12 사용자 요청). 화면과 장면은 같고, 자막을 ElevenLabs 음성으로 읽습니다.

- **읽는 문장:** `src/story/narration-lines.json`. 화면 자막과 같은 문장이고, 숫자와 영문만 소리 나는 대로 씁니다(십 분, 삼 회, 디, 피, 플레오스). 타이틀은 한 줄 소개를, 마무리는 "함께 타는 사람까지 편안한 운전"과 진단 아님 문장을 읽습니다.
- **목소리 만들기:** `python3 tools/tts/narrate.py`
  - 환경 변수 `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`가 필요합니다. 모델은 `eleven_multilingual_v2`입니다.
  - 바뀐 문장만 다시 만듭니다(전체 947자). 음성 파일(`public/tts/`)은 Git에 넣지 않고, 길이만 `src/data/narration.json`에 남깁니다.
  - 음량을 맞추고(−16 LUFS) 앞뒤 무음을 자르며, 문장 안의 쉼은 0.35초까지만 남깁니다. 쉼표 뒤 쉼이 0.4~0.7초라 장면 안에 들어가지 않았습니다.
- **배치(`src/story/narration.ts`):**
  - 자막이 뜨고 0.2초 뒤 읽습니다. 앞 문장이 끝나지 않았으면 기다립니다.
  - 카드 문장은 알림음이 끝나고 0.3초 뒤에 읽습니다. 그래서 알림음과 겹치는 말이 없습니다.
  - 모든 문장이 자기 자막이 떠 있는 동안 끝납니다.
- **화면만 있는 버전과 다른 곳:**
  - **타이틀:** 3.6초에서 6.2초로 늘렸고, 소개 문장의 끝은 첫 장면이 나타나는 동안 이어집니다. 문장 길이만큼 다 잡으면 3:15를 넘습니다.
  - **"카드는 누르지 않아도…" 자막:** 카드가 뜨고 9.3초 뒤가 아니라 6초 뒤에 뜹니다. 약 6초짜리 문장이 장면 안에서 끝나게 하려는 것입니다.
  - **마무리:** 두 문장을 읽느라 9초에서 약 10초로 늘었습니다.
  - 전체 약 3분 14초입니다.

## 만들기

```sh
npm run render-story       # out/motioncare-story.mp4, 이 PC에서 약 3분
npm run render-story-tts   # out/motioncare-story-tts.mp4 (내레이션 버전)
npx remotion still src/index.ts MotionCareStory out/check.png --frame=2100
```

렌더러가 `Page.bringToFront: Session closed`로 멈추면 프로세스가 남아 끝나지 않습니다. 이때는 남은 렌더를 끄고 `--concurrency=4`로 다시 돌립니다.

## 확인한 것

- **숫자:** 자막과 화면의 숫자는 모두 앱 화면의 값입니다.
  - 출발 전과 다음 출발 조언: 1.7회 → 0.5회
  - 11/5 운행: 12분, 정차 직전 큰 감속 5회, 서아 4/5, 주행 중 안내 1회
  - 프로필: −68%
- **카드:** 세 번째 정차로 차가 선 지 약 4.2초 뒤에 알림음이 났습니다(콘솔 기록 279.4초, 앱 로그 283.6초). 규칙은 `GuidancePolicy`의 10분 안 같은 패턴 3번과 정차 뒤 잔잔한 순간입니다. 카드와 알림음은 1배속 그대로입니다.
- **자막 길이:** 가장 긴 자막(40자)도 한 줄에 들어갑니다.
- **마무리의 차량 기능:** 영상에 나온 것만 적었습니다. 차량 속도, 기어, 공조·온도(운행 상세의 차 안 환경), 위치(바깥 대기질), 내비 위 알림 카드입니다.

## 확인하지 못한 것

- 실차. 모든 화면은 에뮬레이터입니다.
- 내비 지도가 그려지지 않는 에뮬레이터라 내비 화면은 비어 있습니다.
- 노트북 창 크기에서 앱 글자가 읽히는지는 사람이 직접 보지 않았습니다.
- 평가한 운행(테스트 주행)과 기록 장면의 운행(11/5)은 다른 운행입니다. 자막은 둘을 같은 운행이라고 말하지 않습니다.
