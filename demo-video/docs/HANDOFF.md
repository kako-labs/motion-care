# 모션케어 데모 영상: 실제 녹화본으로 다시 만들기

## 지금 상태

`reference/motioncare-demo-reference.mp4` (약 3분 29초)가 형식의 기준입니다.
이 영상은 Pleos 에뮬레이터와 Virtual Console을 새로 돌려서 만든 것이 아니라, 기존 6분 시연 영상(`public/source.mp4`) 한 개를 잘라 붙여 만든 것입니다.

- 잘라 온 것: Virtual Console, Pleos 화면, 왼쪽 아래 차량 데이터 패널, "내비 위 카드" 기록 상자, 알림음과 음성
- 새로 그린 것: 맨 위 한 줄, 가감속·좌우 움직임 그래프, 브랜드 소개와 마무리

그래서 Pleos 화면 하나가 1062x597 크기밖에 안 되고, 전체화면으로 키우면 흐립니다. 앱 UI도 6분 영상을 찍던 때의 것입니다.

## 할 일

같은 형식, 같은 장면 순서로, 실제 Pleos 에뮬레이터와 Virtual Console을 다시 돌려 녹화한 화면으로 바꿉니다. 그 사이 앱 UI가 바뀌었다면 바뀐 UI로 찍습니다.

바뀌지 않아야 하는 것(형식):

1. 브랜드 소개 12초 → 네 화면을 하나씩 소개(주행 중) → 정지 → 본편 → 브랜드 마무리 9초
2. 본편의 4분할 배치: 왼쪽 위 Virtual Console, 오른쪽 위 Pleos, 왼쪽 아래 차량 데이터, 오른쪽 아래 움직임 분석 그래프와 카드 기록
3. 설명은 맨 위 한 줄뿐 (단계 표시 + 지금 하는 일 한 문장)
4. 앱만 보여주는 구간(본편 시작부터 차가 움직이기 전까지)은 Pleos 화면만 전체화면
5. 내비만 보이는 주행 구간은 짧게, 카드와 소리가 나오는 순간은 1배속으로 확대
6. 장면 순서와 맨 위 문장: `docs/shot-list.md`

## 녹화본에 필요한 것

### 방법 A (권장, 코드 수정 거의 없음): 같은 배치의 합성 영상을 더 크게

기존 6분 영상과 **똑같은 배치**의 영상을 **3840x2160, 30fps**로 만듭니다. 1920x1080 기준 좌표는 아래와 같고, 3840x2160이면 전부 2배입니다.

| 영역 | x | y | w | h |
| --- | --- | --- | --- | --- |
| Virtual Console | 72 | 112 | 685 | 597 |
| Pleos 화면 | 785 | 112 | 1062 | 597 |
| 차량 데이터 패널 | 71 | 728 | 687 | 328 |
| 내비 위 카드 기록 | 784 | 946 | 1064 | 110 |

이 좌표는 `src/config/layout.ts`의 `CROP`입니다. 화면 코드는 원본을 "1920x1080 좌표계"로 다루기 때문에, 배치만 같으면 해상도가 커져도 코드를 고칠 필요가 없고 그만큼 선명해집니다.
기존 6분 영상의 맨 위 제목 줄과 오른쪽 아래 설명 칸은 새 영상에서 쓰지 않으니 비워도 됩니다.

### 방법 B: 화면별로 따로 녹화

Virtual Console과 Pleos 화면을 각각 원래 해상도로 녹화해도 됩니다. 이 경우 `src/components/Source.tsx`와 `tools/build-remap.mjs`가 화면별 파일을 읽도록 고쳐야 하고, 두 녹화의 시각을 프레임 단위로 맞춰야 합니다. 차량 데이터 패널과 카드 기록은 새로 그려야 합니다.

### 함께 필요한 것

- **소리**: 에뮬레이터 출력(알림음, 음성)이 녹화본 오디오에 들어 있어야 합니다.
- **속도·핸들 기록**: `src/data/telemetry.json` 형식 `{"fps": 10, "speed": [km/h …], "steer": [도 …]}`. 녹화본 0초부터 0.1초 간격입니다. 조작 스크립트나 앱 로그에서 직접 뽑는 것이 가장 정확합니다. 안 되면 `tools/extract_telemetry.py`로 차량 데이터 패널의 숫자를 읽어 만들 수 있습니다(README 참고).

## 그래프를 실제 값으로

지금 오른쪽 아래의 가감속·좌우 움직임 그래프는 계단처럼 각져 있습니다. 재료가 거칠어서입니다.

- 속도는 6분 영상 화면의 숫자를 읽은 것이라 1km/h 단위 정수입니다.
- 핸들은 조작 스크립트가 0° → 30° → −30°로 순간 이동시킨 값입니다.
- 가감속·좌우 값은 앱이 계산한 것이 아니라, 문서의 계산식으로 다시 계산한 것입니다.

새로 만들 때는 아래 순서로 우선합니다. 선을 부드럽게 다듬어 그럴듯하게 만드는 것은 하지 않습니다.

1. **앱이 실제로 계산한 값을 씁니다.** 앱의 탐지 로직이 계산한 가감속과 좌우 움직임(횡가속도 추정)을 시각과 함께 로그로 남기고, 그 값을 그래프에 그립니다. 이 경우 `telemetry.json`에 `accel`, `lateral` 배열(m/s²)을 추가하고 `src/components/Analysis.tsx`의 `motionAt`이 그 값을 읽게 고칩니다.
2. 그게 어려우면 **에뮬레이터가 앱에 준 속도·조향각을 소수점 그대로**, 받은 간격대로 기록해 `speed`, `steer`에 넣습니다. 계산식은 지금 것을 그대로 씁니다.
3. **조작을 사람처럼 합니다.** 핸들은 1~2초에 걸쳐 돌리고, 페달도 서서히 밟고 뗍니다. 순간 이동시키면 실제 값으로 그려도 계단 모양이 됩니다. 단, 급정거·급출발 장면은 카드가 뜰 만큼 충분히 세게 해야 합니다.

그래프 아래의 "입력값 기반 계산" 표시는 1번을 쓰면 "앱이 계산한 값"으로 바꿉니다(`src/config/copy.ts`).

## 녹화 시나리오

`docs/shot-list.md`의 "이 장면에서 하는 조작"을 위에서부터 순서대로 한 번에 녹화하면 됩니다. 길이를 맞출 필요는 없습니다. 길이와 배속은 `timeline.ts`에서 조절합니다.

지켜야 할 점:

- 조작 사이에 1~2초 여유를 둡니다. 구간을 나눌 때 필요합니다.
- 카드가 뜨는 세 장면(`d1-card`, `d2-card`, `d3-card`)은 카드가 뜨기 2초 전부터 사라질 때까지 끊지 않고 찍습니다. 이 구간은 1배속으로 소리와 함께 씁니다.
- 급정거·급출발은 같은 패턴을 3번, 핸들 흔들기는 카드가 뜰 때까지 반복합니다.

화면 소개용으로 **한 장면을 추가로** 찍으면 좋습니다. 지금은 원본에 "앱이 보이면서 달리는 장면"이 13초뿐이라 절반 속도로 늘려 썼습니다.

- 모션케어 앱이 보이는 상태(운행 기록 중)에서 D 기어로 출발해 **30초 이상 직진**하며 0→40km/h로 천천히 가속, 그 뒤 브레이크로 정지.
- 이 장면을 `intro-console` ~ `intro-stop` 다섯 구간의 `src`로 쓰고 1배속으로 맞춥니다.

## 바꿔 끼우는 순서

1. 새 녹화본을 `public/source.mp4`로 넣습니다(기존 파일은 `public/source-old.mp4`로 남겨 둡니다).
2. `src/data/telemetry.json`을 새 녹화본 기준으로 만듭니다.
3. `src/config/timeline.ts`에서 각 장면의 `src: [시작초, 끝초]`를 새 녹화본 시각으로 다시 적습니다. `dur`, `title`, `focus`, `full`, `audio`는 그대로 둡니다. 카드 장면의 `focus.from/to`는 카드가 실제로 뜨고 사라지는 시각에 맞춥니다.
4. UI가 바뀌어 장면이 늘거나 줄면 `timeline.ts`에서 줄을 추가·삭제하고 `title`을 고칩니다. 화면 소개 네 구간의 `id`는 바꾸지 않습니다. 바꾼 내용은 따로 적어 두었다가 끝나고 보고합니다.
5. `node tools/shot-list.mjs`로 장면표를 다시 만들고, `npm run studio`로 확인한 뒤 `npm run render`.

## 확인할 것

- 전체 길이 3분 20초~4분 10초
- 맨 위 문장이 모두 한 줄에 들어감 (가장 긴 문장 기준 36px에서 약 30자)
- 왼쪽 아래 패널의 속도와 Pleos 화면의 속도가 같은 값
- 가감속·좌우 움직임 그래프가 급정거, 핸들 조작과 같은 순간에 움직임
- 그래프 값의 출처(앱 계산값인지, 다시 계산한 값인지)가 화면 표시와 일치함
- 알림음·음성이 카드가 뜨는 순간과 맞음
- Virtual Console 화면을 손대지 않음. 핸들을 돌려도 도로가 직진으로 나오면 그대로 둠
- 영상에 없는 기능을 문장으로 지어내지 않음 (예: 동승자 평가를 실제로 입력하는 장면이 없으면 "평가했다"고 쓰지 않음)

## 스스로 정하고 나중에 보고할 것

중간에 묻지 않고 아래 기준으로 정한 뒤, 끝나고 한꺼번에 보고합니다.

- UI가 바뀐 화면은 새 UI 그대로 찍고, 맨 위 문장이 안 맞으면 화면에 보이는 것에 맞게 고칩니다.
- 없어진 화면은 빼고, 새로 생긴 화면은 흐름상 가장 가까운 자리에 넣습니다. 동승자 평가 입력 화면이 생겼으면 운행 상세 바로 뒤에 넣습니다.
- 6분 영상 끝의 별도 시험 두 가지(2시간 휴식 카드, 속도 권한 거부)는 지금처럼 뺍니다.
- 길이가 3분 20초~4분 10초를 벗어나면 내비만 보이는 주행 구간부터 줄입니다.
