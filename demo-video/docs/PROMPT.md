# 이 폴더의 영상을 실제 녹화본으로 다시 만들 때 AI에게 줄 프롬프트

아래를 그대로 붙여 넣으면 됩니다.

---

# 역할

너는 모션케어 데모 영상을 실제 녹화본으로 다시 만드는 영상 제작 담당이자 Remotion 개발자다.
화면 조작, 녹화, 편집, 렌더, 검수까지 전부 네가 직접 한다. 사람이 대신 해 주는 단계는 없다.

# 배경

`kako-labs/motion-care` 저장소의 `video/demo-4min-kit` 브랜치, `demo-video/` 폴더에 약 3분 30초짜리 데모 영상의 Remotion 프로젝트가 있다.
이 영상은 형식(장면 순서, 화면 배치, 문구)은 확정됐지만, 화면 자체는 예전에 만든 6분 시연 영상 한 개를 잘라 붙인 것이다. Pleos 에뮬레이터와 Virtual Console을 새로 돌린 것이 아니어서 화질이 낮고, 앱 UI도 예전 것이다.

# 목표

같은 형식 그대로, 이 노트북에서 실제 Pleos 에뮬레이터와 Virtual Console을 돌려 녹화한 화면으로 바꾼 최종 영상을 만든다. 앱은 지금 최신 UI로 찍는다.

# 먼저 읽을 것 (이 순서로)

1. `demo-video/docs/HANDOFF.md`: 무엇이 확정이고 무엇을 바꿔야 하는지, 녹화본 규격, 바꿔 끼우는 순서, 확인 목록
2. `demo-video/docs/shot-list.md`: 장면 38개의 순서, 맨 위 문장, 장면마다 해야 하는 조작, 길이
3. `demo-video/reference/motioncare-demo-reference.mp4`: 형식의 기준 영상. 프레임을 뽑아 처음부터 끝까지 직접 확인한다
4. `demo-video/README.md`: 실행 방법과 어느 파일을 고치면 되는지
5. `demo-video/src/config/timeline.ts`: 장면 하나가 한 줄인 편집 파일

기준 영상과 문서를 확인하기 전에는 녹화나 코드 수정을 시작하지 마라.

# 직접 하는 일

- **실행**: Pleos 에뮬레이터, Virtual Console, 모션케어 앱의 빌드·설치·실행을 네가 한다. 실행 방법은 저장소의 `docs/SETUP_WINDOWS.md`, `docs/pleos-emulator/`, `scripts/`를 본다.
- **조작**: 앱 화면 누르기, 탭 이동, 설정 토글, Virtual Console의 기어·페달·핸들·공조 조작을 네가 한다. 화면 조작에는 Ego Lite를 쓴다. Ego Lite로 안 되는 조작은 adb(`input tap`, `am start` 등), 에뮬레이터의 차량 속성 주입, 기존 조작 스크립트 순으로 대신한다.
- **녹화**: 화면과 에뮬레이터 소리를 네가 녹화한다. Ego Lite에 녹화 기능이 있으면 그것을 쓰고, 없으면 `adb screenrecord`, ffmpeg 화면 캡처 등으로 한다.
- **검수**: 녹화본과 렌더 결과에서 프레임을 뽑아 네가 직접 본다. 소리 위치는 ffmpeg로 확인한다.

# 순서

1. `git fetch origin && git checkout video/demo-4min-kit`로 브랜치를 받는다. 위 자료를 읽고 기준 영상의 장면 순서를 파악한다.
2. 이 노트북에서 기존 6분 시연 영상(`motion-care-driving-demo-share.mp4`)을 만들 때 쓴 녹화·합성 도구(에뮬레이터 화면 녹화, Virtual Console 조작 스크립트, 네 화면을 한 장에 합치는 코드)를 찾는다. 있으면 그것을 쓴다. 없으면 같은 배치의 합성 영상을 만드는 도구를 `demo-video/tools/` 안에 새로 만든다.
3. 현재 앱 UI로 `shot-list.md`의 조작을 처음부터 끝까지 해 보고, 예전과 달라진 화면을 목록으로 만든다.
4. `HANDOFF.md`의 "방법 A" 규격으로 녹화한다. 기존과 같은 배치, 가능하면 3840x2160, 30fps, 에뮬레이터 소리 포함. 화면 소개용 직진 주행 장면(30초 이상)도 따로 찍는다. 녹화가 잘못됐으면 그 장면만 다시 찍는다.
5. 그래프에 쓸 값을 기록한다. `HANDOFF.md`의 "그래프를 실제 값으로"를 따른다. 가장 좋은 것은 앱의 탐지 로직이 실제로 계산한 가감속·좌우 움직임 값을 로그로 뽑아 그대로 그리는 것이다. 안 되면 에뮬레이터가 앱에 준 속도·조향각을 소수점 그대로 기록해 `src/data/telemetry.json`을 만든다. 핸들과 페달은 순간 이동시키지 말고 1~2초에 걸쳐 사람처럼 조작한다. `tools/extract_telemetry.py`로 화면 숫자를 읽을 경우, 스크립트 안의 좌표가 1920x1080 기준이니 녹화 해상도에 맞게 고친다.
6. 새 녹화본을 `public/source.mp4`로 넣고(기존 파일은 `public/source-old.mp4`로 보관), `timeline.ts`의 각 장면 `src`를 새 녹화본 시각으로 다시 적는다. 카드 장면의 `focus` 시각도 맞춘다.
7. `npx remotion still`로 장면마다 한 장씩 뽑아 확인하고, 바뀐 구간만 절반 해상도로 먼저 렌더해서 본다. 문제가 없으면 전체를 렌더한다.
8. `HANDOFF.md`의 "확인할 것"을 하나씩 점검한다. 통과하지 못한 항목은 고치고 다시 확인한다.

# 묻지 말고 스스로 정할 것

중간에 사용자에게 묻지 마라. 아래 기준으로 스스로 정하고, 끝난 뒤 무엇을 어떻게 정했는지 한꺼번에 보고한다.

- **UI가 바뀐 화면**: 새 UI 그대로 찍는다. 그 장면의 맨 위 문장이 화면과 안 맞으면, 화면에 실제로 보이는 것에 맞게 한 줄로 고친다.
- **없어진 화면이나 기능**: 그 장면을 뺀다.
- **새로 생긴 화면이나 기능**: 흐름상 가장 가까운 자리에 장면을 추가한다. 예를 들어 동승자 평가를 입력하는 화면이 생겼으면 운행 상세 바로 뒤에 넣는다.
- **조작 순서가 달라진 경우**: 새 UI에서 자연스러운 순서를 따르고, 장면 순서도 그에 맞춘다.
- **길이**: 장면을 넣고 빼서 전체가 3분 20초~4분 10초를 벗어나면, 내비만 보이는 주행 구간부터 줄인다.
- **막힌 경우**: 다른 방법을 먼저 시도한다. 에뮬레이터를 실행할 수 없는 것처럼 네가 풀 수 없는 문제일 때만 멈추고, 무엇을 시도했는지와 함께 보고한다.

# 지켜야 할 것

- 형식을 바꾸지 마라. 화면 배치, 맨 위 한 줄 방식, 앱 소개 구간의 Pleos 전체화면, 브랜드 소개와 마무리는 기준 영상과 같아야 한다.
- Virtual Console은 공식 도구 화면이다. 화면을 가공하거나, 없는 기능을 있는 것처럼 보이게 하지 마라. 핸들을 돌려도 도로가 직진으로 나오면 그대로 둔다.
- 그래프 값을 보기 좋게 다듬거나 지어내지 마라. 화면의 표시 문구는 값의 실제 출처와 같아야 한다(앱 계산값이면 "앱이 계산한 값", 다시 계산했으면 "입력값 기반 계산").
- 영상에 실제로 나오지 않는 기능을 문장으로 쓰지 마라.
- 앱 코드와 `main` 브랜치는 건드리지 마라. 작업은 `video/demo-4min-kit` 브랜치의 `demo-video/` 폴더 안에서만 한다. 로그를 뽑으려고 앱에 코드를 넣어야 한다면, 녹화용 임시 빌드에만 넣고 커밋하지 않는다.
- 기존 파일(`public/source.mp4`, `reference/`)을 덮어쓰거나 지우지 마라. 이름을 바꿔 보관한다.
- 전체 렌더는 오래 걸린다(이전 PC에서 약 30분). 수정할 때는 바뀐 구간만 `--frames`로 뽑아 확인한다.

4. 스스로 정한 것 목록과, 확인 목록 점검 결과, 확인하지 못한 것
