# 운행 기록·분석·탑승자 피드백의 근거

프로필·좌석을 한 운행에 고정하고, 차량 움직임을 기록·분석한 뒤 운행 상세, 출발 전 조언, 동승자 평가로 연결하는 기능을 정리합니다. 패턴 기준값의 연구·실측 근거는 [운전 패턴 탐지 기준](detection-thresholds.md)에 따로 기록합니다.

## 먼저 알아 둘 점

- **관찰된 움직임은 멀미 판정이 아닙니다.** 차량 데이터만으로 탑승자의 증상이나 멀미 발생 여부를 알 수 없습니다.
- **운전 패턴과 동승자 평가는 나란히 저장합니다.** 둘을 임의의 멀미 점수나 운전자 점수로 합치지 않습니다.
- **운행 길이를 보정합니다.** 분석 가능한 시간에 따라 10분당 관찰 횟수로 비교합니다.
- **없는 값은 만들지 않습니다.** 신호 공백은 그래프와 계산에서 끊고, 조향 미수신은 좌우 패턴 0회가 아니라 판정 불가로 봅니다.
- **합성 기록과 차량 기록을 구분합니다.** 각각 `SYNTHETIC`, `VEHICLE` 출처로 저장·표시합니다.

## 담당 기능

| 기능 | 현재 동작 | 사용자에게 주는 정보 |
| --- | --- | --- |
| 프로필·좌석 | 사람을 등록하고 5개 좌석에 배치하며, 운행 시작 시 탑승 구성을 고정합니다. | 누가 운전했고 누가 어디에 탔는지 |
| 운행 원본 저장 | 시각, 속도·조향, 관찰 패턴, 안내 결과를 SQLite에 저장합니다. | 다시 확인할 수 있는 운행 원본 |
| 패턴 분석 | 빠른 출발, 큰 감속, 반복 가감속, 빠른 회전, 반복 좌우 움직임을 찾습니다. | 어떤 움직임이 언제 관찰됐는지 |
| 목록·상세 | 시간·거리, 속도 그래프, 패턴 구간, 환경과 평가를 표시합니다. | 조언이 나온 기록과 구간 |
| 최근 비교·조언 | 같은 운전자의 완료 운행을 비교해 다음 행동 하나를 제안합니다. | 다음 운행에서 바꿔 볼 행동 |
| 완료 평가 | 동승자별 편안함, 불편 상황, 직접·보호자 응답을 저장합니다. | 차량 데이터로 알 수 없는 탑승 경험 |
| 프로필 상세 | 운전자는 운행·패턴 추이, 동승자는 민감도·평가를 확인합니다. | 사람별로 구분한 기록 |

## 전체 데이터 흐름

```text
프로필 등록·좌석 배치
        │ 운행 시작 시 현재 좌석을 TripParticipants로 복사
        ▼
속도·조향 수신 ── 약 1초마다 원본과 분석 결과 저장
        │
        ├─ 속도 변화 → 빠른 출발·큰 감속·반복 가감속
        └─ 속도 + 조향 → 추정 횡가속도 → 빠른 회전·반복 좌우 움직임
        ▼
운행 종료 ── COMPLETED / 미완료 기록은 다음 실행 때 INTERRUPTED
        │
        ├─ 운행 목록·상세·그래프
        ├─ 같은 운전자의 최근 완료 운행 비교
        ├─ 다음 출발 전 행동 하나 제안
        └─ 동승자 평가를 같은 운행에 저장
```

자동차 기기에서는 홈 설정 카드의 "운행 자동 기록"을 켜 두면 기어가 P에서 D·R로 바뀔 때 기록을 만들고, P에서 3분이 지나면 끝냅니다. 기록 중에는 "운행 기록 종료"로 직접 끝낼 수도 있습니다. 차량이 없는 기기는 "샘플 시작" 버튼으로 합성 샘플 기록을 만듭니다. 생성 직후 현재 좌석과 출발 환경을 해당 운행에 고정하고 포그라운드 기록 서비스를 연결합니다. 규칙과 측정은 [운행 자동 기록](auto-record.md)에 있습니다.

## 프로필과 좌석 연결

사람 자체의 정보와 해당 운행의 역할을 분리합니다.

- `PersonProfile`: 이름, 성인·어린이 구분, 멀미 민감도와 선택 특성
- `SeatingPlan`: 지금 차량에 배치한 사람과 좌석
- `TripParticipants`: 운행 시작 시 복사한 운전자·동승자·좌석

운전자·동승자는 사람에게 영구히 붙는 유형이 아니라 그 운행의 좌석으로 정합니다. 현재 좌석을 나중에 바꿔도 이미 저장된 과거 운행의 탑승 구성은 바뀌지 않습니다. 어린이는 운전석에 배치하지 못하게 막습니다.

프로필은 `motion-care-profile.db`의 `people`, `current_seats`, `trip_participants`, `trip_feedback`에 나눠 저장해 현재 좌석과 과거 좌석을 혼동하지 않습니다.

## 운행 원본과 저장 수명

주행 데이터는 `motion-care-trips.db`에 저장하며 프로필·환경 DB와 스키마를 따로 관리합니다.

| 저장 항목 | 의미 |
| --- | --- |
| `TripRecord` | 운행 ID, 시작·종료 시각, 상태, 차량 ID, 데이터 출처 |
| `SpeedSample` | 시작 후 경과시간, m/s 속도, 유효 상태 |
| `SteeringSample` | 시작 후 경과시간과 조향각 원본 |
| `Observation` | 패턴 종류, 관찰 시각·구간, 탐지기 버전 |
| `GuidanceEvent` | 안내 주제, 판단 시각, 표시·생략·실패 결과 |

표본, 관찰, 조향, 안내 결과를 약 1초마다 같은 트랜잭션으로 묶어 저장합니다. 쓰기가 실패하면 다음 주기나 종료 때 다시 시도합니다. 프로세스가 강제 종료되면 마지막 약 1초의 값은 잃을 수 있습니다.

Activity가 재생성되어도 Application 범위 Repository가 유지되어 기록은 계속됩니다. 새 프로세스에서 끝나지 않은 운행은 완료로 꾸미지 않고 `INTERRUPTED`로 보존합니다.

## 분석과 10분당 비교

두 속도 표본이 모두 유효하고 시각이 증가하며 간격이 5초 이하일 때만 이어진 구간으로 봅니다.

- 분석 시간: 유효하게 이어진 표본 간 시간의 합
- 거리: 이웃한 두 속도의 평균 × 시간 간격
- 패턴 횟수: 저장된 `Observation`의 종류별 개수
- 비교 가능 조건: 분석 시간이 1분 이상인 완료 운행

```text
10분당 빈도 = 관찰 횟수 × 600,000ms ÷ 분석 가능한 시간(ms)
```

| 패턴 | 입력 | 현재 판정 요약 |
| --- | --- | --- |
| 빠른 출발 | 속도·시간 | 정차 후 3초 안에 2.0m/s² 이상 가속 |
| 정차 직전 큰 감속 | 속도·시간 | 정차 전 5초 안에 2.0m/s² 이상 감속 |
| 반복 가감속 | 속도·시간 | 0.9m/s² 이상 가감속 방향이 30초 안에 3번 전환 |
| 빠른 회전 | 속도·조향 | 추정 횡가속도 2.0m/s² 이상 |
| 반복 좌우 움직임 | 속도·조향 | 추정 횡가속도 0.9m/s² 이상으로 좌우가 30초 안에 3번 전환 |

앞뒤 가감속은 약 1초 구간의 속도 차이로 근사합니다. 좌우 움직임은 `속도² × tan(조향각 ÷ 조향비) ÷ 축거`로 추정하므로 실제 횡가속도 센서나 요레이트 측정값이 아닙니다.

## 운행 상세와 그래프

- 저장된 속도 표본의 실제 해상도로 그래프를 그립니다.
- 유효하지 않거나 5초 넘게 끊긴 구간은 선을 연결하지 않습니다.
- 패턴을 고르면 관찰 시각·구간과 해당 지점의 속도를 확인할 수 있습니다.
- 완료·중단·기록 중 상태를 구분합니다.
- 운전자·동승자·좌석, 평가 유무, 조향 지원 여부를 함께 표시합니다.
- `0회`와 `판정할 수 없음`을 구분합니다.

최대 속도, 거리, 분석 시간, 횟수와 10분당 빈도는 해당 `TripSnapshot`에서 계산합니다. 화면을 그럴듯하게 보이게 하려고 없는 표본을 보간하거나 가짜 곡선을 만들지 않습니다.

## 출발 전 조언

같은 운전자의 `COMPLETED` 운행 중 분석 가능한 기록만 사용합니다.

1. 최근 최대 3회에서 패턴별 10분당 평균을 계산합니다.
2. 평균 빈도가 가장 높은 패턴 하나를 고릅니다.
3. 대응하는 행동 한 가지를 출발 전 조언으로 표시합니다.
4. 자료가 있으면 최근 최대 3회와 그 이전 최대 3회의 평균을 비교합니다.

프로필의 "최근 운전 경향"과 "왜 이 조언인가요?" 화면도 같은 비교를 씁니다. "왜 이 조언인가요?"의 계산 방법에는 마지막 운행 한 건의 계산식과, 평균에 들어간 운행별 빈도를 함께 보여 줍니다. 패턴별 값은 최근 최대 3회의 평균이고, 화살표와 %는 그 이전 최대 3회 평균과의 차이입니다. 그래서 홈 조언과 프로필이 같은 "최근" 값을 보여 줍니다. 이전 운행에 해당 패턴이 없었으면 %를 계산하지 않습니다. 아래 "전체 운전 기록" 그래프는 운행마다 한 점이라, 끝점은 마지막 운행 하나의 값입니다.

> 정차 시 조금 일찍 감속해 보세요.

> 정차 직전 속도 변화 · 최근 3회 평균 1.4회/10분 · 이전 3회 평균 2.4회/10분

빈도가 줄었다는 것은 해당 운전 패턴이 덜 관찰됐다는 뜻일 뿐, 멀미 감소나 운전 실력 향상을 뜻하지 않습니다. 동승자 평가는 같은 운행의 맥락으로 보여 주지만 조언 선정 점수에는 넣지 않습니다.

## 완료 평가

운행 뒤 동승자마다 다음을 선택적으로 남깁니다.

- 편안함 1~5점, 척도 버전 `COMFORT_5_V1`
- 불편했던 상황: 출발·정차, 반복 가감속, 커브, 좌우 움직임 등
- 응답자: 동승자 본인 또는 보호자

`(운행 ID, 동승자 ID)`별 한 건을 저장하고 다시 들어와 수정할 수 있습니다. 건너뛰기는 0점이나 불편 없음으로 저장하지 않고, 수정 도중 건너뛰어도 기존 응답을 임의로 삭제하지 않습니다.

## 화면별 데이터

| 화면 | 주로 읽는 데이터 |
| --- | --- |
| 홈·출발 전 | 현재 좌석, 운전자, 최근 완료 운행, 조언과 최근 비교 |
| 프로필 선택·상세 | 등록된 사람, 좌석, 운전자별 운행 추이, 동승자별 민감도·평가 |
| 운행 목록 | 상태, 시각, 시간·거리, 당시 탑승자, 평가 유무 |
| 운행 상세 | 속도·조향 원본, 패턴, 환경, 안내 결과, 탑승자 평가 |
| 조언 이유 | 선택 패턴, 횟수, 분석 시간, 최근·이전 빈도와 계산 한계 |
| 완료 평가 | 해당 운행에 저장된 동승자와 기존 응답 |

## 검증 상태와 한계

| 확인한 내용 | 아직 확인하지 못한 내용 |
| --- | --- |
| Repository 재생성 뒤 프로필·좌석·평가·운행 기록 보존 | 장기간 실차 운행의 DB 크기와 보관 기간 |
| 단위 검사와 공개 주행 데이터·표준 사이클 판정 | 국내 실차 신호에서의 오탐·누락 |
| 일반 Android 에뮬레이터와 Pleos 통합 화면 흐름 | 실제 차량의 다양한 해상도와 주행 제한 전체 |
| 여러 동승자, 보호자 응답, 수정·건너뛰기 저장 | 평가 문항과 실제 멀미 경험의 관계 |

- 실차 속도·조향의 갱신 간격, 지연, 조향각 정의를 확인하지 못했습니다.
- 좌우 움직임은 차량 가정을 포함한 추정입니다.
- 어린이와 국내 승용차에서 기준과 조언 효과를 검증하지 못했습니다.
- 실제 내비 경로의 곡률, 교통량, 앞차 거리, 도로 상태를 분석하지 않습니다.
- 보관 기간과 자동 삭제 정책은 아직 정하지 않았습니다.
- 일반 Android·합성 데이터 검증을 Pleos 실차 검증으로 표현하지 않습니다.
