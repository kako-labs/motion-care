# 조언 상세와 경로의 통행 가능성 확인

## 사용자 요청

조언의 이유를 궁금해서 들어오는 화면이므로 숫자 3개와 짧은 팁을 넘어, 관찰한 구간·집계 기준·비교·우선순위·다음 행동을 설명한다. 지도는 실제 자동차로 갈 수 있는 경로인지 질문했다.

## 설명 화면

- 최근 운행의 정차 전 큰 감속 5개를 시각·전후 속도·소요 초로 제시. 선택한 구간의 전후 12초/8초 속도와 해당 감속 구간을 확대해서 보여준다.
- 같은 구간을 운행 상세에서도 열 수 있다. 조언에서 고른 사건과 상세 그래프의 선택이 일치한다.
- 계산 기준을 접어서 제공: 현재 공유 `PatternDetector`의 마지막 5초·1초 속도 변화·2.0m/s² 기준과 같은 정차 중복 집계 제외를 설명한다. 탐지기나 임계값은 수정하지 않았다. 현재 브라우저의 사건은 기존 합성 리플레이 fixture라는 사실은 데이터·인계 문서에 유지한다.
- 원래 '최근 3회 1.4회'는 실제로 이번 운행 5/37×10의 값이었다. **최근 1회 1.4회/10분**, **직전 2회 평균 2.7회/10분**, **최근 3회 평균 2.3회/10분**으로 구별해 수정했다.
- 순위는 같은 운전자의 분석 가능한 완료 기록, 운행별 10분당 빈도, 최근 3회의 산술평균을 사용한다. 기준은 기존 기록 담당 `HistoryInsights.kt`의 `adviceFor`다. 이번 브라우저는 보존된 3회만 비교하고 없는 '이전 3회'를 만들지 않는다.
- 최근 세 운행에서 가장 빈도가 큰 항목을 고르는 기존 방식이다. '직전보다 악화된 항목'을 고른다는 잘못된 인상을 없앴다.
- 동승자 응답은 참고 기록으로 설명하고 조언 선정 점수에 반영됐다고 주장하지 않는다.
- 분석 1분 미만·완료되지 않은 기록은 제외한다. 운전자에게 기록이 없으면 개인화된 감속 근거를 만들지 않는다.

현재 기록의 시간·속도·사건은 합성 데이터이며 실제 운전 성적이 아니다. 제품 UI에는 사용자 요청대로 반복적인 목업·면책 문구를 넣지 않고 데이터와 이 문서에 출처를 유지한다. 실제 앱에서는 저장된 Sample/Observation과 ViewModel의 기존 집계를 연결한다.

## 지도 확인 결과

같은 공개 지점을 자동차용 OSRM `route/v1/driving`에 다시 요청했다. `code=Ok`, 대안 2개, 약 5,797m와 5,563m로 저장 응답과 일치했다. 요청 지점에서 도로에 스냅된 거리는 출발 약 11.9m, 도착 약 26.5m다. 그래서 표시 지점 이름은 역 자체의 특정 출입구가 아니라 **양재역/봉은사역 부근**이다.

- 도로·방향·통행 조건을 가진 지도 그래프에서 자동차 경로로 연결된 결과다. 화면에 임의로 그린 길이 아니다.
- OSRM은 사용 프로필로 이동 수단과 통행 처리를 정한다. [공식 API](https://project-osrm.org/docs/v5.24.0/api/), [자동차 프로필](https://github.com/Project-OSRM/osrm-backend/blob/master/profiles/car.lua).
- 현재 공사·임시 통제·현장 표지·해당 차량의 제약과 실제 통행을 확인한 것은 아니다. 최신 실차 내비게이션의 안내를 대신하는 확정적 통행 보장으로 표현하지 않는다.
- 실제 차종별 주행, 현장 답사, 실시간 교통, 개인별 멀미 완화 효과는 검증하지 않았다.

## 이번 검증

Ego에서 홈 → 이유 보기, 감속 3번 선택, 계산 기준 펼치기, 운행 상세의 같은 3번 사건으로 이동을 확인했다. 수치 5회·1.4·2.7, 항목 순위, 4개 화면 크기의 가로 잘림·이미지 상태를 확인했다. 네이티브 코드·공통 계약·내비 SDK는 이 설명 화면 변경에 포함되지 않는다.

## 기록이 쌓인 지영 시나리오

지영에게도 별도의 합성 운행 3개(j1~j3)를 추가했다. 최근 운행은 32분 중 31분 분석·감속 4회, 이번 1.3회/10분·직전 2회 평균 2.1회/10분이다. 홈의 최근 목록도 현재 운전자의 3회만 보여준다. `?driver=jiyoung#why`로 해당 상태를 바로 열 수 있다. 기록 없음 상태 자체는 유지하되 이번 시연에는 지영의 기록이 있는 상태를 사용한다.


## 기본 진입과 상세 감속 곡선

기본 운전자를 지영, 선택 운행을 j1로 변경했다. URL 인자 없이 열어도 지영의 최근 기록 3개와 상세 근거가 나타난다. 이전 저장 상태에는 시나리오 버전을 적용해 빈 운전자 상태를 이 기본값으로 이행한다. 초기화도 같은 기록 있는 상태로 돌아간다. 현재 세션에서 좌석을 바꾸는 기능은 유지한다.

상세 그래프는 감속 전 24초부터 정차 뒤 36초까지 접근·제동·대기·재출발을 보여준다. 균일한 직선 감속 대신 제동 압력이 점진적으로 변하는 곡선을 사용한다. 상세 0.2초 표본과 전체 1초 표본은 같은 합성 속도 함수에서 생성하며 공통 시각의 값이 일치한다. 실제 차량에서 수집한 5Hz 자료로 주장하지 않는다. 거리도 같은 표본으로 다시 적분한다. 기존 detector 정책이나 차량 수집 코드는 변경하지 않았다.

6개 기록의 표본 일치·감속 단조 감소·기록 공백, Ego의 기본 진입·사건 선택·포인터 값·같은 운행 상세 연결·초기화·재진입·이전 빈 상태 이행을 검증했다. 상세 그래프는 4개 화면 크기에서 가로 잘림과 잘못된 좌표가 없었다.
