## 실행 순서와 허용 범위

1. 각 작업 트리의 status·branch·diff를 확인한다. 원격 main과 PR #10/#17 상태를 읽기 전용으로 확인하고, 필요하면 분리된 브랜치·작업 트리에서 통합안을 만든다. 기존 준비 브랜치나 미커밋 작업을 파괴하지 않는다.
2. 기존 담당 화면과 ViewModel, 저장·프로필·평가 흐름을 읽는다. `feature/history` 안의 담당 화면에 확정 B 표시를 연결한다. 정적 시제품 수치를 실제 운행 데이터처럼 삽입하지 않는다.
3. 실제 화면은 기존 Repository·ViewModel의 값을 사용하고 공백·미응답·짧은 기록 처리도 유지한다. HTML의 0.2초 상세 표본을 실차 수집 주기로 주장하거나 실제 1Hz 자료를 측정하지 않은 5Hz 자료로 바꾸지 않는다.
4. 지영의 기록 3건·선택 운행 j1은 **시연 기본값**이다. Android에서도 기존 개발·테스트 fixture 경로가 있으면 그 경로에 격리해 재현한다. 일반 사용자 DB에 가짜 운행을 자동 주입하거나 실제 기록 없음 상태를 숨기지 않는다.
5. 앱 홈·공통 조립 등 팀원 소유 영역이 필요한 부분은 연결 지점·리뷰 가능한 패치·인계 문서를 준비한다. 팀원 코드·공통 계약·DB·Gradle·SDK·권한·서비스·탐지 정책·내비 흐름을 임의로 변경하지 않는다. 경계 밖 수정 없이 가능한 담당 영역은 계속 완성한다.
6. 지도는 OSM 도로와 OSRM 저장 경로 응답 기반이다. 편안한 경로·환경 기능을 새 핵심 MVP로 확대하지 않는다. 커브·노면 데이터나 검증하지 않은 예방 효과를 지어내지 않는다. 연결되지 않은 장면은 기존 범위를 문서로 구별한다.
7. 변경에 맞는 단위 검사, 표준 `python scripts/dev.py verify`와 필요한 UI 검증을 실행한다. 실제 에뮬레이터에서 변경 화면이 표시되고 기존 평가 저장·재진입이 되는지 확인한다. 실행하지 못한 항목은 정확히 남긴다.
8. 별도 브랜치·Draft PR에서 저장하고 촬영 순서·남은 연결을 갱신한다. 사용자 지시 없이 공유 main 병합·강제 푸시·최종 제출을 하지 않는다.

사용자는 추가 동의·의견 질문 없이 진행하길 원한다. 이미 확정한 색·컨셉을 다시 고르게 하거나 단순히 “진행할까요?”라고 묻지 않는다. 경계 밖 작업은 무단 확장하지 말고 구체적인 인계물로 남긴다.

## 확인 가능한 최신 상태

- B 색상·유리 질감·사선 패널, 왼쪽 큰 차량과 정교한 얼굴 자산 유지.
- HTML 기본값은 지영 운전·서아 동승, 지영 운행 3건. 새로 열기·초기화·이전 빈 저장 상태 이행 확인.
- 최근 지영 운행: 32분 중 31분 분석, 감속 4회, 1.3회/10분, 직전 2회 평균 2.1회/10분.
- 감속 그래프는 접근·제동·정차·재출발, 시각·km/h 축, 포인터 값과 동일 사건 상세 이동을 제공.
- 6개 합성 리플레이의 상세/전체 값 일치, 조언 계산 검사, 브라우저 동작 7개와 화면 크기 4개 검사 통과. 표준 Android verify 통과. **새 B 전체 화면의 Android 적용·최종 통합 APK 촬영 검증은 남아 있다.**
