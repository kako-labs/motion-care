## 준비한 것과 실제 구현을 구별하기

| 영역 | 현재 준비물 | 촬영에서의 표시 |
| --- | --- | --- |
| 출발·프로필·운행 상세·평가 | 클릭 가능한 B HTML 시제품 | `UI 시제품 · 합성 데이터` |
| 환경 값·미지원·권한·오래된 값 | HTML의 고정 상태 6종, 기존 모델을 받는 Compose 표시 컴포넌트 | HTML은 합성. 실제 앱으로 촬영할 때만 차량/예측 출처 표시 |
| 주행 기록·패턴·내비 위 안내·환경 수집 | 공유 main의 기존 구현을 확인함. 이번에는 수정하지 않음 | 실제 최신 앱의 에뮬레이터 실행을 별도로 촬영 |
| 편안한 경로 | OSM 실제 도로와 OSRM 저장 응답으로 옵션·회전 안내 비교 | `경로 기능 콘셉트 · 실제 탐색 미연결` |
| Android B 표시 컴포넌트 | 운행 상세·동승자 프로필·평가·사선 유리 패널·환경 표시의 stateless Compose 코드 | 컴파일 가능한 준비물. 기존 화면에 연결·촬영하기 전에는 APK 적용 완료로 소개하지 않음 |

환경 데이터 수집을 다시 만들지 않는다. `EnvironmentRepository.current/history`를 쓰는 것이 기존 구조다. 이번 Compose 컴포넌트는 `EnvironmentSnapshot?`만 받아서 표시하며 API·권한·서비스·공조 제어를 추가하지 않는다.

네이티브 준비 코드는 [android/](android/)에 사본을 둔다. 공유 저장소 브랜치의 `feature/history/.../presentation/`가 실제 검증 위치다. `BHistoryPanels.kt`는 기존 ViewModel의 값을 받아 그리는 운행 상세·프로필·평가 컴포넌트이며 저장·탐지·시작/종료 정책을 새로 만들지 않는다. 별점과 선택 이유는 호출자가 관리하고 건너뛰기는 별도 콜백이다.

편안한 경로는 노션 E04에서 후순위·담당 미배정이다. 이번 사용자 지시에 따라 **시연용 개념 흐름만** 준비했다. 핵심 MVP나 담당자를 바꾸지 않았다.

## 혼자 리허설하기

1. 화면을 열고 상단 `시연 도구 → 처음으로 초기화`를 누른다.
2. 좌석 → 환경 → 경로 비교 → 출발 안내 → 운행 기록 → 완료 평가 순서로 눌러 본다.
3. 4점과 커브를 선택해 저장한 뒤 운행 상세의 응답을 확인한다. 건너뛰면 `미응답`이다.
4. 환경 상태 6종과 경로 연결 실패를 한 번씩 확인한다.
5. 최종 영상은 실제 앱 장면과 콘셉트 장면의 자막을 나눠 녹화한다. 제품 UI의 합성·면책 문구는 11/8 사용자 지시에 따라 제거했으며, 발표 자료와 인계 문서에서 실제 연결 범위를 구분한다.

실제 촬영 전에는 통합 APK의 고정 커밋, 에뮬레이터 버전, 패턴 입력과 실제 표시 결과를 한 번 대조해야 한다. 이번 준비가 실제 SDK 연결·실차 검증·최종 접수까지 완료했다는 뜻은 아니다.

[경로와 그래프의 목적·데이터·근거](ROUTE-AND-CHART-2026-11-08.md). 지도는 실제 도로 좌표, 그래프는 1Hz 리플레이와 감속 사건·기록 공백을 함께 표시한다. 제품 UI의 장황한 합성·면책 문구를 제거했다.
