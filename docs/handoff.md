## 홈 화면에서 남은 것

- 홈은 `Home2` 시안 배치로 `app`의 `home` 패키지에 있습니다. 칸마다 지금 구현된 기능만 연결했고, 뺀 칸과 이유는 [디자인 기록](design.md#앱에-구현한-홈-화면)에 있습니다.
- 기록 담당 PR #20을 합칠 때 큰 카드에 출발 조언과 "왜 이런 조언을 받았나요?", 사람 카드에 좌석·운전자와 B 좌석 화면, 안내 카드에 출발 안내 스위치, 하단 탭에 기록 목록을 연결합니다. PR #20도 `MainHost`를 고쳐 이 파일에서 충돌이 납니다.
- 세로형 창에서는 카드를 세로로 쌓지만 실제 나눈 창 크기는 측정하지 않았습니다.

## 차량 입력에서 남은 것

- 속도와 조향을 저장합니다. 브레이크 등이 필요해지면 입력과 저장을 추가합니다.
- 기록 실패는 로그로만 남습니다. 권한 회수나 입력 중단을 화면에 알려야 합니다.
- 속도 권한을 두 번 거부하면 요청 창이 다시 뜨지 않습니다. 이때 홈 화면 위쪽 안내 띠에 "설정 > 권한 > 위치에서 허용하면 기록할 수 있어요"와 "설정 열기"를 보여 Car Settings의 앱 정보를 엽니다. Pleos 차량 설정에는 앱별 위치 권한 화면이 없습니다. [측정](pleos-emulator/README.md#속도-권한-거부)
- 위치 SDK 권한(대기질용)을 거부하면 기록은 계속되지만 바깥 대기질과 환경 카드가 빠지며, 화면에는 알리지 않습니다.
- 주행 중에 앱 화면을 보여 주려면 `MainActivity`에 `distractionOptimized`를 선언하고 주행 제한을 직접 따릅니다. 지금은 주행 중 앱 화면이 가려져, 기록 종료는 주차 후에 합니다.
- `TripRepository`를 바꾸면 각 테스트의 가짜 구현도 함께 고쳐야 합니다. 공용 테스트 구현으로 합치는 것을 이때 함께 처리합니다.

## 패턴 탐지에서 남은 것

- 기준값은 [근거 문서](detection-thresholds.md)로 정했지만 실제 차량 신호로 다시 측정해야 합니다. 에뮬레이터 속도는 입력 순간 계단처럼 바뀌어 정확도를 판단할 수 없습니다.
- 횡가속도 추정에 쓰는 축거와 조향비는 기준 차량의 값입니다. 차량 프로필에서 실제 값을 받으면 `LateralLimits`로 넘겨야 합니다.
- 조향 없는 주행과 있는 주행을 비교할 때는 좌우 패턴을 함께 비교하지 않습니다.
- 상세 화면은 횟수만 보여 줍니다. 10분당 횟수 정규화와 운행 비교는 기록 집계에서 다룹니다.

## 주행 중 안내에서 남은 것

- 규칙 값의 대부분은 제품 판단입니다. [근거 문서](guidance-card.md)의 유형을 보고 실차 주행과 팀 의견으로 조정합니다.
- 음성은 주행 담당이 에뮬레이터에서 듣고 잘 나오는 것을 확인했습니다. 실차 음량과 음질은 미확인이고, 음성과 알림음 음색 조정은 급하지 않아 나중에 합니다. 재생 결과는 저장하지 않고 logcat의 `GuidanceSound`에만 남습니다.
- 알림이 꺼져 있으면 카드는 `FAILED`로 기록되고, 홈 화면 "안내" 카드의 스위치 아래에 알리며 "알림 켜기"로 요청 창이나 설정 화면을 엽니다. 이때 "안내 소리" 선택은 숨깁니다. 상세 화면에는 "주행 중 안내 없음"으로 보입니다. [근거](guidance-card.md#알림이-꺼져-있을-때)
- 메시지 카드가 App Market에서 막히면 `GuidancePresenter` 구현을 앱 안 배너와 알림 센터로 바꿉니다.
- 환경 카드는 대기질과 차의 내기·외기 상태가 어긋날 때만 주행당 한 번 뜹니다. 패턴 카드가 우선이고 15분 간격을 함께 씁니다. 30분 같은 값은 제품 판단입니다. [근거](guidance-card.md#환경-카드)
- 주행 시간 카드는 쉬지 않고 2시간을 달릴 때마다 뜹니다. 15분 넘게 멈추면 쉰 것으로 보고 다시 셉니다. 2시간과 15분은 졸음 예방 휴식 지침(Highway Code Rule 91)의 값이고 멀미 기준이 아닙니다. §15에 문구가 없어 문구는 제품 판단입니다. [근거](guidance-card.md#주행-시간-카드)
- 카드 문구는 최종 기획 §15의 기본 조언에서 가져와 `guidanceCopy`에 고정했습니다. 출발 조언(기록 담당)도 같은 표를 쓰면 표현이 어긋나지 않습니다.

## 환경에서 남은 것

- 홈 화면에 현재 값 네 가지를 표시합니다. 출발 전·주행 상세(기록 담당)는 `EnvironmentRepository`의 `current`와 `history`를 읽고, 값의 상태와 출처, "대기질: Open-Meteo, CAMS 예측" 표시를 함께 보여 줘야 합니다. [근거](environment.md#상태)
- 위치 권한 요청 창 문구가 "알 수 없는 작업 실행"으로 나옵니다. 권한에 이름표가 없어 생기는 시스템 문구라 앱에서 바꿀 수 없습니다.
- 대기질은 실측이 아닌 예측값입니다. 실측이 필요해지면 `OpenMeteoAirSource`를 에어코리아로 바꾸고 키 보관 방법을 정합니다.
- 에뮬레이터의 바깥·실내 온도는 고정값이었습니다. 실차 값은 확인하지 못했습니다.

## 운영사무국에 확인할 것

- `distractionOptimized` 선언과 `android.car.permission.CAR_SPEED`, `pleos.car.permission.CAR_DRIVE` 권한의 승인 여부
- 멀미 안내를 `CATEGORY_MESSAGE` 알림으로 보내도 심사를 통과하는지
- `pleos.car.permission.TTS_SERVICE`와 온디바이스 TTS를 앱 등록 없이 배포해도 되는지. My Project의 TextToSpeech SDK 접근은 문서상 "Coming Soon"입니다
- `pleos.car.permission.FUSED_LOCATION`, `pleos.car.permission.CAR_CLIMATE`, `android.car.permission.CAR_EXTERIOR_ENVIRONMENT` 권한의 승인 여부

구현되지 않은 데이터 API를 미리 모두 넣지 않습니다. 기능을 시작할 때 해당 도메인의 Repository·입력·상태·인수 기준을 정합니다. 최초 기획서의 상세 계약은 참고이며 실제 공개 API는 docs/contracts.md와 코드가 기준입니다.
