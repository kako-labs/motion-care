# B 화면 정교화 및 CI 복구

사용자는 차량 그림은 유지하고, 나머지 UI의 과한 생성형 시안 느낌을 줄여 정교한 제품 화면으로 다듬도록 요청했다. 기존 디자인 확인 질문 없이 진행하라는 선호를 유지한다.

## 결정

- 차량/얼굴 원본, 네이비·하늘색, 절제된 유리 질감과 사선 제안은 유지한다.
- 원형 아바타 링·대형 플러스·겹친 좌석 라벨은 작은 좌석 표면과 간결한 이름으로 바꾼다. 빈 좌석은 작고 균일한 추가 표시, 선택만 하늘색으로 강조한다.
- 장식용 반복 카드·영문 번호·광택과 굵은 테두리를 줄인다. 제목·핵심 수치·본문·보조 글자의 위계를 통일한다.
- 표면은 네이비의 미세한 명도 차이와 얇은 경계로 나눈다. 빛 효과는 차량에 양보하고 입력/선택 상태만 또렷하게 한다.
- 출발, 기록, 프로필, 조언/그래프, 평가, 종료와 HTML 환경/경로까지 같은 기준을 적용한다. 상태·콘텐츠·저장 동작은 유지한다.
- Apple HIG의 레이아웃·타이포·재질이라는 설계 관점을 참고하되, Apple 자산·SF 글꼴을 가져오거나 플랫폼을 바꾸지 않는다. 구체적인 수치와 표현은 이번 제품의 판단이다. 참고: https://developer.apple.com/design/human-interface-guidelines/

## 대안과 선택 이유

전체를 밝은 미니멀 테마로 바꾸면 승인한 B와 차량의 분위기가 사라진다. 기존 네온/글래스를 더 강화하면 지적받은 과한 인상이 커진다. 따라서 색과 차량은 보존하고 정보의 밀도·표면·조작 요소를 정리한다.

## 범위

feature/history의 표시와 HTML 아카이브를 수정한다. CI 복구 요청으로 app/androidTest의 낡은 ScaffoldFlowTest만 현재 화면 흐름 및 실제 저장 조회에 맞춘다. 팀원의 app 제품 코드·core·DB·SDK·서비스·탐지·내비 계약은 변경하지 않는다. 앱 루트 테마 통합은 리뷰용 패치로만 준비한다.

지영 시연 3건은 debug/HTML에만 유지한다. 일반 사용자 DB를 합성 기록으로 채우지 않는다. 이전 버전은 save/history-b-before-refinement-20261108 브랜치로 보존했다.

## 완료 기준

실패한 CI 전체 UI 검사를 갱신해 실제 통과를 확인한다. 공개 Repository를 통한 샘플 3개와 재생성 후 보존·평가 왕복 검증을 유지한다. HTML 4개 대표 크기와 모든 화면의 시각 검토, Android 빌드/단위 검사 및 실제 화면·터치 검증을 수행한다. 로컬 검사와 원격 CI 결과를 구분해 기록한다.
