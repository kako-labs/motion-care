# 앱 화면 모음 만들기

Pleos 에뮬레이터에서 앱의 모든 화면을 찍어, 설명을 붙인 한 페이지로 묶는 방법입니다. 팀원과 화면을 함께 점검하고 PR 전후를 비교할 때 썼습니다.

- **결과:** [모션케어 홈 화면 점검](https://claude.ai/artifact/BUkCqMkXLwRfaxAP5zEc9w) (Claude 아티팩트, 링크가 있으면 볼 수 있음)
  - 이미지 106장을 담았습니다. 2026-11-09에 만들고 PR이 합쳐질 때마다 같은 주소로 갱신했습니다.
- **캡처 도구:** [`docs/pleos-emulator/tools/capture_screens.py`](pleos-emulator/tools/capture_screens.py)

## 페이지 구성

- **머리:** 기준 커밋, 포함한 PR 범위, 날짜를 적습니다. "실제 앱을 에뮬레이터에서 찍었고 실차가 아니며, 영상용으로 만든 기록"이라는 한 줄도 함께 둡니다.
- **구역:** '지금 화면'이 맨 위입니다. 그 아래에 이전 점검을 최신순으로 둡니다(PR #27 전후 비교, PR #23 점검, PR #21·#22 시점).
  - 구역마다 "바뀐 것" 상자에 PR 번호와 한 줄 설명을 적습니다.
- **묶음:** 사용 흐름 순서로 묶습니다. 홈 → 운행 → 좌석과 사람 → 기록과 상세 → 이동 평가 → 프로필 → 조언 근거 순서입니다. 관련된 두 장은 나란히 둡니다.
- **캡션:** 상태 이름과 파일 번호를 붙이고, 그 화면에 실제로 보이는 것만 설명합니다. 숫자는 화면의 값을 그대로 씁니다. 이미지를 직접 본 뒤에 씁니다.
- **alt 텍스트:** 화면의 주요 글자와 값을 적습니다. 이미지가 안 떠도 내용을 알 수 있게 하기 위해서입니다.
- **전후 비교:** 같은 에뮬레이터, 같은 데이터, 같은 스크립트로 찍습니다. 왼쪽이 전, 오른쪽이 후입니다.
- **보기 편의:** 이미지를 누르면 크게 보이고, ←→로 넘깁니다.
  - 어두운 차량 화면에 맞춰 어두운 테마를 씁니다.
  - 한 열로 읽게 하고, 좁은 화면에서는 나란히 놓은 두 장을 세로로 쌓습니다.

## 만드는 순서

1. **기기를 확인합니다.** 같은 노트북에서 다른 세션도 에뮬레이터를 씁니다. `adb -s emulator-5600 emu avd name`이 `pleos`인지 확인하고, 그 기기만 씁니다.
2. **빌드하고 설치합니다.**

   ```sh
   ./gradlew :app:assembleDebug
   adb -s emulator-5600 install -r app/build/outputs/apk/debug/app-debug.apk
   ```

3. **데이터를 넣습니다.**
   - 사람·좌석은 `demo_data.py`로 한 번 넣습니다. 에뮬레이터 키보드로 한글을 칠 수 없어 프로필 DB에 넣습니다.
   - 3주치 기록 20건은 `demo_history.py` 또는 `film_takes.py restore`로 넣습니다.
4. **찍습니다.**

   ```sh
   ANDROID_SERIAL=emulator-5600 python3 docs/pleos-emulator/tools/capture_screens.py <폴더>          # 화면 17장
   ANDROID_SERIAL=emulator-5600 python3 docs/pleos-emulator/tools/capture_screens.py <폴더> drive    # 주행 중·종료·평가
   python3 docs/pleos-emulator/tools/film_takes.py restore                                          # drive 뒤 기록 되돌리기
   ```

   - `static`(기본)은 아무것도 저장하지 않습니다. 바꾼 설정 스위치는 찍은 뒤 바로 되돌리고, 이동 평가는 고르기만 하고 뒤로 나옵니다.
   - `drive`는 가상 차량으로 짧게 달려 운행을 하나 남깁니다. 그래서 끝나면 기록을 되돌립니다.
5. **한 장으로 모아 봅니다.** 명령은 `magick montage <폴더>/*.jpg -tile 6x -geometry 420x302+4+4 sheet.jpg`입니다. 빈 칸, 로딩 중 화면, 같은 화면이 두 번 찍힌 곳, 의도와 다른 화면이 없는지 봅니다.
6. **페이지를 만듭니다.** HTML 한 장과 `img/` 폴더로 구성합니다.
   - 이미지 이름은 구역 접두사로 나눕니다: '지금 화면'은 `n_`, 전후 비교는 `u_before_`·`u_after_`
7. **게시합니다.** Claude Code의 Artifact 도구로 HTML과 `img/*.jpg`를 여러 파일 아티팩트로 올립니다.
   - 고칠 때는 같은 주소로 다시 올리고, 버전 이름에 바뀐 내용을 적습니다(예: "PR #38 운행 상세 속도 개선 반영").
8. **링크를 남깁니다.** Notion 작업 페이지에 링크를 적습니다.

## 배운 것

- **앱 창만 자릅니다.** 화면은 2560×1440입니다. 앱 하나가 앱 영역 전체를 쓰는 창은 (853, 90)에서 1682×1210입니다(`pleos-emulator/README.md`). 시스템 막대와 주행 화면을 빼야 화면끼리 비교하기 쉽습니다.
- **고정 대기보다 글자를 기다립니다.** 앱을 막 켜면 홈의 조언 칸이 잠깐 비어 있습니다(PR #38). 그래서 "왜 이 조언인가요?"가 나타날 때까지 기다린 뒤 찍습니다.
- **스크롤 전에 탭을 누릅니다.** 프로필의 '운전할 때·동승할 때' 탭은 화면 위에 있어서, 아래로 넘긴 뒤에는 찾지 못했습니다.
- **같은 화면이 두 번 찍히지 않게 합니다.** 운행 상세는 두 번 넘기면 끝에 닿습니다. 세 번째 장은 두 번째와 같았습니다.
- **손으로 누르지 않습니다.** uiautomator(`--user 10`)로 화면 글자를 찾아 그 중심을 누릅니다. 그래야 PR 전후를 같은 순서로 다시 찍을 수 있습니다.
- **상태를 남기지 않습니다.** 바꾼 설정은 되돌리고, 저장 버튼은 누르지 않습니다. 기록이 생기는 조작은 마지막에 하고, 끝나면 되돌립니다.
- **데이터의 출처와 한계를 페이지에 적습니다.** 생성한 기록과 에뮬레이터 고정값(바깥 기온 25°C)이 그런 것입니다.
- **크기:** JPEG(`-q:v 3`) 한 장이 약 230~250KB입니다. 이미지를 지연 로딩하면 100장을 넘겨도 페이지가 무겁지 않습니다.

## 다른 AI에게 맡길 때

아래 프롬프트의 대괄호를 채워서 넘깁니다. 이 저장소에서는 값이 이미 정해져 있어서 그대로 써도 됩니다.

```text
너는 [모션케어]의 화면 점검 페이지를 만든다. Android 에뮬레이터에서 실제 앱 화면을 찍어, 설명을 붙인 HTML 한 페이지(이미지 여러 장 포함)로 묶고, 링크로 공유할 수 있게 게시한다. 보는 사람이 앱을 설치하지 않고도 모든 화면과 상태를 훑어보고, 무엇이 바뀌었는지 알 수 있어야 한다.

[입력]
- 저장소: [motion-care], 빌드: [./gradlew :app:assembleDebug], APK: [app/build/outputs/apk/debug/app-debug.apk]
- 기기: [ANDROID_SERIAL=emulator-5600], AVD 이름 [pleos], 사용자 [--user 10]
- 화면 [2560x1440], 잘라 낼 앱 창 [x=853, y=90, 1682x1210]
- 데이터 준비: [demo_data.py 한 번, demo_history.py] / 되돌리기: [film_takes.py restore]
- 캡처 도구: [docs/pleos-emulator/tools/capture_screens.py] (없으면 아래 방식으로 만든다)
- 기준 커밋과 PR 범위: [main SHA, PR #a–#b] / 전후 비교가 필요하면 비교할 커밋: [이전 SHA]
- 기존 페이지가 있으면 그 주소: [아티팩트 URL] (같은 주소로 갱신한다)

[순서]
1. adb -s <기기> emu avd name 으로 대상 AVD인지 확인하고 그 기기만 쓴다. 다른 작업이 쓰는 에뮬레이터는 건드리지 않는다.
2. 빌드·설치하고 데이터를 준비한다. 에뮬레이터 키보드로 한글을 칠 수 없으니 이름 같은 값은 데이터 도구로 넣는다.
3. 찍을 화면 목록을 먼저 만든다. 화면마다 상태(켜짐·꺼짐, 빈 상태, 안내 문구, 권한 거부, 주행 중, 종료 후)를 나누고, 각 화면에 가는 조작을 적는다.
4. 스크립트로 찍는다. uiautomator dump로 화면 글자를 찾아 중심을 탭하고, adb exec-out screencap -p로 찍고, 앱 창만 잘라 JPEG로 저장한다. 파일 이름은 <번호>_<화면>.
   - 고정 sleep 대신 그 화면의 특정 글자가 나타날 때까지 기다린다.
   - 바꾼 설정은 바로 되돌리고 저장 버튼은 누르지 않는다. 기록이 생기는 조작은 마지막에 하고, 끝나면 데이터를 되돌린다.
   - 사람이 손으로 누르지 않는다. 다시 돌리면 같은 화면이 나와야 한다.
5. 찍은 것을 montage로 한 장에 모아 직접 본다. 빈 칸, 로딩 중, 같은 화면 중복, 의도와 다른 화면이 있으면 스크립트를 고쳐 다시 찍는다.
6. 페이지를 만든다(아래 규칙). HTML 한 장과 img/ 폴더.
7. 여러 파일 아티팩트로 게시한다. 고칠 때는 같은 주소로 다시 올리고, 버전 이름에 바뀐 내용을 적는다.

[페이지 규칙]
- 맨 위: 제목, 기준 커밋과 PR 범위, 날짜, "실제 앱을 에뮬레이터에서 찍었고 실차가 아니며, 시연용 데이터"라는 한 줄.
- '지금 화면' 구역이 먼저, 이전 점검은 아래에 최신순. 구역마다 "바뀐 것" 상자에 PR 번호와 한 줄 설명.
- 화면은 사용 흐름 순서로 묶고, 관련된 두 장은 나란히 둔다. 전후 비교는 같은 기기·데이터·스크립트로 찍어 왼쪽 전, 오른쪽 후.
- 캡션은 상태 이름 + 파일 번호, 그리고 그 화면에 실제로 보이는 것만. 숫자는 화면 값을 그대로 쓴다. 이미지를 직접 보고 확인한 뒤 쓰고, 추측하지 않는다.
- alt 텍스트에 화면의 주요 글자와 값을 적는다.
- 데이터의 출처와 한계(생성한 기록, 에뮬레이터 고정값)를 밝힌다.
- 이미지를 누르면 크게 보고 ←→로 넘긴다. 지연 로딩. 어두운 테마, 한 열 읽기 폭, 약 400px 폭에서도 가로 스크롤 없이.
- 실명, 개인 경로, 키는 넣지 않는다. 사람은 역할이나 시연용 이름으로 부른다.

[끝나면 보고]
게시한 주소, 찍은 화면 수, 찍지 못한 화면과 이유, 데이터를 되돌렸는지, 확인하지 못한 것.
```
