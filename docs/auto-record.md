# 운행 자동 기록

자동차 기기에서 홈 설정 카드의 "운행 자동 기록"을 켜 두면, 기어가 주행을 시작하고 끝냅니다. 홈 하단의 "운행 시작" 버튼은 없앴습니다. 차량이 없는 기기는 합성 샘플을 쓰므로 "샘플 시작" 버튼이 그대로 남습니다. 규칙은 `data:trip`의 `AutoTripPolicy`, 기어 구독은 `CarGearSource`, 실행은 `GearDriveWatcher`와 `app`의 `TripRecordingService`에 있습니다.

## 먼저 알아 둘 점

- **팀 문서의 방향을 따릅니다.** Notion [화면 플로우](https://app.notion.com/p/40bae4c07fd681fba28dd7031c9928ea)는 "① 켜기·끄기: 차량 앱에서 기능 ON/OFF, 켜짐 유지·자동 시작 조건"과 "출발 전 수동 ON → 실제 세션 이벤트가 성립하면 자동 시작 확장"을 적었습니다. [화면별 기능 분해](https://app.notion.com/p/40cae4c07fd681c8a2ccea86f375f100)는 "자동 시작·종료는 실제 제공 신호·앱 수명주기 검증 후 우선 적용", "일시 정차를 운행 종료로 오인하지 않도록 시작·종료 조건과 중복 방지를 정의", "기록 수집을 끌지는 별도 설정으로 명시"를 요구합니다. 2026-11-10에 "켜 두면 상시로 기록되는" 스위치로 정했습니다.
- **시작과 끝의 값은 제품 판단입니다.** 기어로 운행을 나누는 기준을 다룬 연구나 표준을 찾지 못했습니다. 아래 표에 유형을 나눠 적습니다.
- **실차 전원 동작은 확인하지 못했습니다.** 시동을 끈 뒤 헤드유닛이 꺼지는지 잠드는지에 따라 마지막 몇 분의 처리가 달라집니다. [확인하지 못한 것](#확인하지-못한-것)에 적습니다.

## 규칙

```text
P ──(D 또는 R)──> 주행 시작 ──> 기록 ──(P)──> 3분 대기 ──> 주행 끝
                                   ↑            │
                                   └──(D·R·N)───┘  대기 초기화, 같은 주행 계속
```

근거 유형: **팀 문서**(Notion 기획) / **실측**(우리가 측정) / **공식 문서** / **제품 판단**(근거 없음, 이유만 있음) / **구현 판단**.

| 항목 | 현재 | 유형 | 근거와 한계 |
| --- | --- | --- | --- |
| 켜기 | 기본 꺼짐. 켤 때 속도·위치·알림 권한을 묻고, 속도를 허용해야 켜짐 | 팀 문서·제품 판단 | 화면 플로우의 "원할 때만 사용". 속도 없이는 기록할 값이 없음 |
| 시작 | P에서 D나 R로 바뀔 때. 켤 때 이미 D면 바로 시작 | 제품 판단 | `GEAR_SELECTION` 수신은 에뮬레이터에서 확인([차량 신호](pleos-emulator/README.md#차량-신호)). 시동·탑승을 알리는 API는 확인하지 못함 |
| 끝 | P에서 3분 | 제품 판단 | 사람이 내리거나 잠깐 세우는 정차로 한 번의 운행을 나누지 않으려는 값. 연구 근거 없음 |
| 끝 시각 | P로 바꾼 때. 그 뒤 3분 동안 저장된 속도·조향·관찰·안내 결과는 지움 | 구현 판단 | 기다린 3분이 운행 시간에 들어가면 10분당 빈도(`HistoryInsights`의 유효 분석 시간)가 낮아지고 운행 시간이 3분 길어짐 |
| N | 시작도 끝도 하지 않고 P 대기를 초기화 | 제품 판단 | 세차장처럼 N에서 차가 움직이는 경우 |
| 직접 종료 | "운행 기록 종료"를 누르면 끝나고, P를 거친 뒤에야 다시 시작 | 제품 판단 | 운전자가 누른 종료 때문에 같은 운행이 둘로 나뉘지 않게 함 |
| 기어 신호가 끊김 | 시작도 끝도 하지 않고 P 대기는 유지 | 구현 판단 | 차량 서비스 재시작 중에는 `RestartingSubscription`이 다시 구독할 때까지 값이 없음 |
| 잠든 뒤 출발 | P에서 3분 넘게 지난 뒤 D가 오면 앞 주행을 P로 바꾼 때로 끝내고 새 주행을 시작 | 구현 판단 | 헤드유닛이 잠들면 확인 타이머가 멈추고, 깨어난 뒤 D가 먼저 올 수 있음. 시계는 잠든 시간까지 세는 `elapsedRealtime` |
| 확인 간격 | 5초 | 구현 판단 | 3분에 비해 충분히 짧음 |
| 주행 사이 | 포그라운드 서비스를 유지하고 알림 "운행 자동 기록 켜짐" | 실측 | 일반 서비스는 앱이 뒤로 가고 60초 뒤 종료([백그라운드 기록](pleos-emulator/README.md#백그라운드-기록)) |
| 다시 켜짐 | 부팅(`BOOT_COMPLETED`)·앱 업데이트(`MY_PACKAGE_REPLACED`) 수신기와 앱을 열 때 서비스를 시작 | 공식 문서·실측 | Android 12부터 백그라운드에서 포그라운드 서비스를 못 켜지만 이 두 방송은 예외([Android 문서](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start#background-start-restriction-exemptions)) |
| 출발 때 저장 | 좌석의 사람과 환경 값 | 구현 판단 | 화면이 열려 있지 않아도 서비스가 저장. 화면과 서비스가 함께 저장하려 하면 `TripPreparation`이 한 번만 저장 |
| 끝난 뒤 화면 | 홈 큰 카드에 종료 카드(주행 상세·평가) | 제품 판단 | 직접 종료와 같음. 중단된 주행에는 띄우지 않음 |

## 측정

2026-11-10 Pleos 에뮬레이터(v2.1.0, API 34)에서 `auto_record_e2e.py`를 두 번 돌렸습니다. 첫 번째는 대기 60초, 끝 시각 처리를 넣기 전 APK이고, 두 번째는 대기 30분, 최종 APK입니다. 자세한 값은 [측정 기록](pleos-emulator/README.md#운행-자동-기록)과 [로그](pleos-emulator/logs/auto_record_e2e.log)에 있습니다.

| 항목 | 결과 |
| --- | --- |
| 기어 권한 | `CAR_POWERTRAIN`은 설치 때 허용됨(요청 창 없음) |
| 켜기 | 스위치를 누르면 속도·위치·알림 요청 창 3개, 모두 허용하면 켜지고 서비스가 포그라운드로 시작 |
| 대기 | 내비를 앞에 두고 P에서 60초, 1804초 동안 서비스 유지 |
| 시작 | D로 바꾸고 1.1초 뒤 "운행 기록 중"(두 번 모두) |
| 끝 | P로 바꾸고 약 186초 뒤 주행 완료. 알림은 끝날 때의 환경 값을 저장한 뒤라 약 196초에 바뀜 |
| 끝 시각 | 처리 전에는 약 37초 주행이 222초·샘플 1411건으로 저장됨. 처리 후에는 37.6초·샘플 240건, 최근 기록에 "1분 미만" |
| 끝난 뒤 화면 | 홈 큰 카드에 "운행을 마쳤어요"와 이동 평가·주행 상세·완료 |
| 재부팅 | 다섯 번 중 네 번은 부팅 완료 뒤 12~19초에 서비스가 켜지고 D로 2.4초 뒤 기록 시작. 한 번은 부팅 수신기용 프로세스가 10초 안에 붙지 못해 시스템이 종료(`start timeout`)하고 방송을 놓침. 그때는 앱을 열 때까지 기어를 보지 않음 |
| 앱 업데이트 | 다시 설치하고 약 2초 뒤 서비스가 다시 켜짐(두 번 모두) |
| 끄기 | 스위치를 끄면 서비스와 알림이 사라짐 |
| 백그라운드 시작과 위치 | 부팅으로 켜진 서비스(앱을 열지 않음)에서도 바깥 대기질 이유가 "위치 없음"이 아니라 "네트워크"였음. 위치는 받았고 에뮬레이터 인터넷이 없어 대기질만 못 받음 |

## 확인하지 못한 것

- **실차 전원:** 시동을 끈 뒤 3분이 지나기 전에 헤드유닛이 꺼지면 그 주행은 다음 부팅 때 "중단"으로 남고, 끝 시각은 다시 켜진 때가 됩니다(기존 중단 처리). 잠들었다 깨면 P로 바꾼 때로 끝납니다. 시동 상태 속성(`IGNITION_STATE`)은 Virtual Console에 없어 쓰지 않았습니다.
- **Android 15:** `targetSdk` 35인 앱이 Android 15에서 돌면 `BOOT_COMPLETED` 수신기가 `dataSync` 포그라운드 서비스를 켤 수 없고([Android 15 변경](https://developer.android.com/about/versions/15/behavior-changes-15#fgs-boot-completed)), `dataSync`는 하루 6시간까지만 돕니다([시간 제한](https://developer.android.com/develop/background-work/services/fgs/timeout)). Pleos는 API 34라 해당하지 않습니다. 앱은 부팅 시작이 거부되면 기록만 남기고, 시간 제한이 오면 서비스를 멈춥니다. 플랫폼이 15로 올라가면 다른 서비스 유형이나 방식을 다시 정해야 합니다.
- **부팅 방송을 놓칠 때:** 위 측정처럼 부팅 직후 부하로 프로세스 시작이 늦으면 시스템이 방송을 건너뜁니다. 다시 보내지 않으므로 그날은 앱을 열어야 기록이 켜집니다. 실차의 부팅 부하는 모릅니다.
- **프로세스 종료:** 서비스는 `START_NOT_STICKY`라 시스템이 프로세스를 종료하면 앱을 열거나 다시 부팅할 때까지 기어를 보지 않습니다. 기록 중이던 주행은 다음 실행 때 "중단"이 됩니다.
- **App Market:** 상시 포그라운드 서비스와 부팅 시작이 심사를 통과하는지 확인하지 못했습니다.
- **주행 중 조작:** 설정 카드의 스위치는 주행 중에도 바뀝니다. 주행 제한(UxR 80)은 아직 처리하지 않았습니다([주행 중 화면 표시](design.md#주행-중-화면-표시)).
