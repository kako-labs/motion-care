## 앱명 / 프로젝트명

모션케어(가칭) / motion-care

## 1. 앱 한 줄 소개

차량 데이터로 운전자의 반복 가감속 습관을 분석해, 멀미에 민감한 동승자가 더 편안하도록 다음 출발 전에 바꿀 행동 하나를 알려주는 차량용 앱입니다.

## 2. 기획 배경

팀원 한 명은 어린 시절부터 차멀미를 겪었고, 가족도 이를 줄이려고 여러 방법을 시도했습니다. 아이가 차에서 힘들어해도 운전자는 어떤 운전이 영향을 줬는지 모른 채 다음 이동을 맞습니다. 이 경험에서 두 가지 불편에 주목했습니다.

- **운전자는 자신의 운전이 동승자에게 어떻게 느껴지는지 알기 어렵습니다.** 5개국 4,479명을 대상으로 한 온라인 설문(Schmidt 외, 2020)에서 멀미 경험 응답은 뒷좌석 46.4%, 운전석 17.2%였습니다. 운전자는 같은 차에서도 불편을 덜 겪는다고 답하므로, 반복되는 가감속을 스스로 알아차리기 어렵다고 판단했습니다. 이 수치는 자기보고 설문이며 한국 유병률은 아닙니다.
- **운전 데이터가 동승자의 편안함으로 이어지지 않습니다.** 운전점수 서비스는 주로 안전과 보험 관점에서 급가속·급감속을 점수로 보여 줍니다. 우리는 같은 데이터를 함께 탄 사람의 편안함과 다음에 바꿀 행동으로 연결하는 데 주목했습니다.

어린이도 주요 대상입니다. 브라질 7~12세 831명 조사(Henriques 외, 2014)에서는 43.4%가 차량 멀미를 보고했습니다. 국내 아동에 그대로 적용할 수는 없지만, 어린이에게도 드물지 않은 문제임을 시사합니다.

운전을 바꾸는 접근을 뒷받침하는 연구도 있습니다. 움직임의 방향과 시점을 예측하기 어려울수록 증상이 늘었다는 슬레드 실험(Kuiper 외, 2020, 17명)이 있고, 운전자–승객 16쌍의 실도로 30분 연구(Xie 외, 2026)에서는 실시간 가속 피드백과 경고가 운전을 바꾸고 증상 시작을 늦췄습니다. 다만 Xie 연구의 진동 노출 지표(MSDV)에는 차이가 없었고, 주행 중 피드백이라는 점에서 출발 전 조언 중심인 우리 앱과 조건이 다릅니다. 우리 앱의 효과는 아직 확인하지 않았으며, 위 연구 결과를 예상 효과로 쓰지 않습니다.

## 3. 앱 주요 기능 및 차량 특화 요소

### 핵심 기능

| 기능 | 내용 | 해결하는 문제 |
| --- | --- | --- |
| 출발 전 조언 | 지난 운행을 바탕으로 바꿔 볼 행동 하나와 이유를 보여 줍니다. | 무엇을 바꿔야 할지 모르는 문제 |
| 운전 패턴 분석 | 속도와 시간으로 가감속을 근사해 빠른 출발, 정차 직전 큰 감속, 반복 가감속을 찾습니다. | 스스로 알아차리기 어려운 습관 |
| 운전자·동승자·차량 프로필 | 주행마다 운전자 한 명과 동승자 여러 명을 연결합니다. 역할은 사람이 아니라 주행에 저장합니다. | 누구와 탔을 때의 기록인지 구분 |
| 운행 후 동승자 평가 | 주행이 끝나면 불편 정도와 불편했던 상황을 묻습니다. 건너뛸 수 있고, 건너뛰어도 "불편 없음"으로 저장하지 않습니다. | 동승자의 경험을 입력 부담 없이 반영 |
| 주행 상세와 근거 | 관찰된 패턴, 최근 운행 비교, 동승자 평가, 조언 이유와 한계를 보여 줍니다. | 조언을 믿고 따를 근거 |
| 환경 안내 | 외부 대기질과 온도, 차량에서 지원되는 실내 정보를 출처·갱신 시각과 함께 보여 줍니다. 지원되지 않는 값은 추정하지 않습니다. | 운전 외에 점검할 수 있는 요소 |
| 주행 중 짧은 안내 | 내비 화면 위에 작은 카드로 행동 하나를 잠깐 보여 주고 자동으로 사라집니다. 조작을 요구하지 않고, 같은 안내가 반복되지 않도록 간격을 둡니다. 소리는 오디오 정책을 확인한 뒤 추가합니다. | 주행 중 습관을 바로 환기 |

조언은 한 번에 하나만 보여 줍니다. 한 번의 운행으로 습관을 단정하지 않고, 기록이 쌓인 정도에 따라 "관찰됐어요", "반복되고 있어요", "줄어들고 있어요"로 표현을 나눕니다. 운전 패턴과 환경 정보를 하나의 멀미 점수로 합치지 않습니다.

운행 요약 문장 생성과 동승자의 선택 음성 기록은 핵심 흐름을 완성한 뒤 추가합니다. 요약 생성이 실패해도 관찰 결과는 그대로 볼 수 있습니다.

### 차량 특화 요소

- **차량 신호를 직접 사용합니다.** 속도, 기어, 조향, 브레이크를 차량 플랫폼에서 받아 기기 거치 상태와 무관하게 분석합니다.
- **행동을 바꿀 수 있는 순간에 보여 줍니다.** 주행 중 경고보다 출발 전 정차 상태에서 조언을 주어 운전 부담을 줄입니다.
- **함께 타는 사람을 기준으로 합니다.** 운전자 개인의 점수 대신, 오늘 탄 동승자와 그 동승자가 남긴 평가를 조언에 반영합니다.
- **주행 제한에 맞춰 화면을 바꿉니다.** 메인 화면은 출발 전, 주행 중, 종료 후에 따라 구성이 달라지고, 프로필 편집과 긴 기록은 주행 중에 제한합니다.
- **내비와 함께 동작합니다.** 내비를 쓰는 동안 앱은 뒤에서 기록을 이어 가고, 필요한 안내는 내비 화면 위에 잠깐 보여 줍니다.

### 기존 접근과의 차이

| 구분 | 기존 접근 | 모션케어 |
| --- | --- | --- |
| 운전점수 서비스 | 주로 안전·보험 관점의 점수 | 동승자 편안함을 위한 다음 행동 |
| 멀미 제로(현대차·기아 사내 시제품) | 앰비언트 조명, 뒷좌석 화면 표시, 계기판 지수로 주행 중 단서 제공 | 앱만으로 출발 전 코칭과 동승자 기록을 연결 |
| Apple Vehicle Motion Cues | 휴대폰 화면 가장자리에 움직임 표시 | 운전 자체를 바꾸는 쪽에 집중 |
| 운전자 코칭 연구(Xie 외, 2026) | 주행 중 실시간 피드백 | 출발 전 조언과 누적 기록 중심 |

운전자에게 피드백을 준다는 점은 선행 사례와 겹치므로 "최초"라고 주장하지 않습니다. 차이는 대상, 개입 시점, 동승자 기록을 연결한 조합에 있습니다.

## 4. 주요 사용 시나리오

멀미에 민감한 초등학생 자녀를 태우고 주말마다 이동하는 부모가 중형 전기차를 운전하는 상황입니다.

1. **처음 사용:** 운전자, 자녀, 차량을 등록합니다. 기록이 없으므로 앱은 "운전 패턴을 알아가는 중이에요"와 기본 준비 안내, 현재 환경을 보여 줍니다.
2. **출발 전:** 오늘 탈 사람과 차량을 확인하고 운행 기록을 시작합니다.
3. **주행 중:** 내비를 켜고 운전합니다. 앱은 뒤에서 속도와 시간을 기록합니다. 반복되는 패턴이 감지되면 내비 위에 짧은 안내가 잠깐 떴다 사라집니다. 운전자가 조작할 일은 없습니다.
4. **도착 후:** 주차한 뒤 기록을 마치고 자녀에게 묻습니다. "오늘 이동은 어땠나요?"에 "조금 불편했어요", "무엇이 가장 불편했나요?"에 "출발·정차"를 고릅니다. 묻기 어려우면 건너뜁니다.
5. **다음 출발 전:** 앱이 행동 하나를 제안합니다.

   > 지난 도심 주행에서는 정차 직전 속도 변화가 반복됐어요. 오늘은 정지 지점보다 조금 일찍 감속해보세요.

6. **궁금할 때:** "왜 이런 조언을 받았나요?"를 눌러 관찰 횟수, 비교 조건, 자녀의 평가, 조언의 한계를 확인합니다.
7. **기록이 쌓이면:** 같은 동승자, 같은 차량의 운행끼리 비교해 "정차 직전 큰 속도 변화가 최근 3회 운행에서 줄어들고 있어요"처럼 변화를 보여 줍니다. 이 변화는 운전 패턴의 변화이며 멀미 감소를 뜻하지 않습니다.

### Pleos Connect SDK·API 사용 계획

Pleos Connect 에뮬레이터 v2.1.0(API 34)에서 시험 앱으로 직접 확인한 결과입니다. 실차와 App Market 권한 승인은 아직 확인하지 못했습니다.

| --- | --- | --- |
| 속도 | `CarPropertyManager`의 `PERF_VEHICLE_SPEED`, `android.car.permission.CAR_SPEED` | 수신 확인. 10Hz 요청에 초당 약 6.8건, 최대 간격 203ms. Vehicle SDK 2.3.2에는 속도 API가 없어 이 경로를 사용 |

| 주행 중 화면 | Activity의 `distractionOptimized` 선언, 주행 제한 상태 반영 | 미선언 화면은 5km/h부터 가려지고, 선언 화면은 40km/h에서도 표시됨 |

| 주행 중 안내 | `CATEGORY_MESSAGE` 알림 | 40km/h 주행 중 내비 위 상단에 약 9초 표시되고 사라짐. 일반 알림은 뜨지 않음. App Market 승인과 소리는 미확인 |
| 대기질 지역 | Pleos FusedLocation 또는 사용자가 고른 지역 | 문서 확인, 미실행 |
| 실내 환경 | Vehicle SDK 공조 기능 | SDK에서 기능 확인, 미실행. 실내 값 제공 여부는 미확인이며 지원되지 않으면 미지원으로 표시 |
| 외부 환경 | 공공 또는 외부 대기질·날씨 API | 제공처 확정 전 |
| 후속 케어 | NaviHelper의 `RouteOption.COMFORTABLE`, TTS | 문서 확인, 후순위 |

### 분석 방식

1. 속도(m/s)와 수신 시각을 저장하고, 누락·역순·오래된 값은 분석에서 제외합니다.
2. 속도 변화량을 시간 변화량으로 나눠 종방향 가감속을 근사합니다. 가속도 센서 측정값이라고 표현하지 않습니다.
3. 값을 패턴으로 분류합니다. 반복되는 움직임을 보는 이유로 3축 가속 실험(Souman 외, 2026, 107명)을 참고합니다. 이 실험은 0.2Hz 부근의 증상 증가를 보고했지만 다른 주파수에서도 증상이 나타났으므로, 특정 주파수로 증상을 판정하지 않습니다.
4. 운행별로 집계하고 10분당 횟수로 정규화합니다.
5. 같은 운전자·동승자·차량의 운행끼리 비교합니다.
6. 검토한 근거와 규칙으로 조언을 고릅니다. 연구의 실험값을 멀미 판정 기준으로 쓰지 않으며, 임계값은 실제 수신 주기와 합성 입력으로 확인한 뒤 정합니다.

저크(가속도 변화율)는 값이 노이즈에 민감하므로 실제 데이터 품질을 확인한 뒤 추가합니다.

### 구조와 현재 구현

Kotlin, Jetpack Compose로 개발하며 주행, 프로필, 화면 기능을 7개 Gradle 모듈로 나눠 두 사람이 병행 개발합니다. 데이터는 차량 안에 저장하고 핵심 기능은 자체 서버 없이 동작합니다. LLM 요약을 추가할 경우에만 API 키를 앱 밖에 보관하는 중계 함수를 둡니다.

2026-11-03 기준으로 합성 입력의 시작·저장·목록·상세 흐름과 프로필 저장이 동작하며, 단위 테스트 24개와 UI 테스트 2개를 CI에서 실행합니다. 차량 입력, 패턴 분석, 조언, 환경, 평가는 구현 전입니다.

## 6. 기대효과 및 발전 가능성

### 사용자 가치

- **운전자:** 점수 대신 다음 출발에 시도할 행동 하나를 얻습니다.
- **동승자:** 주행 중 입력 없이, 도착 후 짧은 평가로 자신의 경험을 전할 수 있습니다.
- **가족:** 누구와 탔을 때 어떤 패턴이 있었는지 기록으로 확인할 수 있습니다.

모션케어는 멀미를 진단하거나 치료하는 의료 앱이 아닙니다. 우리 앱의 멀미 완화 효과는 아직 확인되지 않았습니다. 작동 증명(에뮬레이터 시연), 사용성(이해도와 방해 여부), 실제 증상 효과를 구분해 검증합니다. 이번 공모전 기간에는 앞의 두 가지를 확인합니다.

### 타깃 고객

| 구분 | 대상 | 사용 이유 |
| --- | --- | --- |
| 1차 | 멀미에 민감한 자녀를 자주 태우는 부모 | 반복 이동이 많고 동기가 분명함 |
| 1차 | 멀미가 심한 가족·연인을 태우는 운전자, 장거리 가족 이동이 잦은 운전자 | 동승자와의 이동 경험 개선 |
| 2차 | 어린이 통학차량, 가족 대상 렌터카, 택시·셔틀 | 승객 편안함이 서비스 품질과 연결됨 |

앱의 직접 사용자는 운전자이며, 동승자에게는 지속적인 조작을 요구하지 않습니다.

### 예상 MAU와 Retention

아래 수치는 실측이나 시장 통계가 아니라 검증할 가정입니다. 활성 사용자는 한 달에 운행을 1건 이상 기록한 사용자로 정의합니다.

| 차량 10만 대 기준 | 보수 | 기본 | 낙관 |
| --- | --- | --- | --- |
| 설치율 | 3% | 5% | 8% |
| 설치자 중 월간 활성 비율 | 30% | 40% | 50% |
| 예상 MAU | 900 | 2,000 | 4,000 |

| 지표 | 목표 | 근거 |
| --- | --- | --- |
| 30일 Retention | 30% | 동승자와의 이동이 반복될 때마다 조언이 갱신됨 |
| 90일 Retention | 20% | 프로필과 기록이 쌓일수록 비교 가치가 커짐 |

습관이 개선되면 사용 동기가 줄어드는 것이 가장 큰 위험입니다. 동승자가 바뀌거나 환경이 달라질 때 새 조언을 주고, 장거리 이동 준비와 케어 기능으로 이용 상황을 넓혀 대응합니다.

### 사용자 확보와 사업 모델

- **확보:** Pleos App Market에서 가족·동승자 케어 앱으로 노출하고, 어린이 동승 가족을 대상으로 "함께 타는 사람까지 편안한 운전"을 알립니다.
- **사업 모델 가설:** 개인 기능은 기본 무료로 제공하고, 통학차량·렌터카·셔틀에는 운행 품질 리포트를 유료로 제공하는 방안을 검토합니다. 구매자와 사용자가 누구인지는 인터뷰로 확인합니다.

### 서비스 확대 계획

1. **이동 전후 지원:** 휴식을 포함한 경로 계획, 움직임 부담을 고려한 경로 후보를 제공합니다. "멀미 안 나는 길"이라고 보장하지 않습니다.
2. **이동 중 케어:** 화면 대신 먼 풍경을 보게 돕는 음성 콘텐츠, 불편할 때 휴식 장소 찾기를 제공합니다.
3. **휴대폰 보고서와 차량 특성별 안내:** 정차 후 고른 보고서만 휴대폰으로 전달합니다.
4. **연구 협력:** 앱 데이터만으로는 실제 멀미 여부와 시점을 알 수 없으므로 자율주행 학습 데이터로 직접 쓰지 않습니다. 앱에서 발견한 질문(어떤 조언이 감속 습관을 바꾸는가 등)을 현대차그룹의 별도 동의·통제 실험으로 발전시켜, 정차·재출발 컴포트 제어와 승차감 평가 기준 연구로 잇는 구조를 제안합니다.

### 개인정보 원칙

운행 기록과 프로필은 차량 안에 저장하고 삭제할 수 있게 합니다. 동승자 평가는 선택이며, 연구 목적으로 자동 활용하지 않습니다. 외부로 데이터를 보내는 기능을 추가할 때는 전송 항목과 동의를 먼저 정합니다.
