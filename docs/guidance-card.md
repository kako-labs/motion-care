# 주행 중 안내 카드의 근거

`GuidanceLimits`의 값, `guidanceCopy`의 문구, `GuidanceSoundPlayer`의 소리 규칙마다 출처와 확인 수준을 적습니다. 값을 바꾸면 이 문서와 [`detection-limits/measure_guidance.py`](detection-limits/measure_guidance.py)의 `Rule`을 함께 고칩니다.

## 먼저 알아 둘 점

- **규칙 값 대부분은 제품 판단입니다.** 주행 중 안내를 몇 번 반복됐을 때 몇 분 간격으로 띄워야 하는지 직접 답하는 연구를 찾지 못했습니다. 표에 유형을 나눠 적습니다.
- **카드는 탐지한 패턴에 맞는 행동 하나를 권합니다.** 동승자의 증상이나 멀미 여부를 판단하지 않습니다. 카드가 운전을 바꾸거나 멀미를 줄이는지는 검증하지 않았습니다.
- **정차 중이 안전하다고 주장하지 않습니다.** NHTSA 지침은 신호 대기처럼 멈춘 상황도 P 기어가 아니면 주행으로 봅니다. 잔잔한 순간을 기다리는 규칙은 차가 흔들리는 중에 카드를 띄우지 않으려는 것이고, 카드를 보는 부담이 없다는 뜻이 아닙니다.

## 규칙

```text
패턴 관찰 ─ 같은 패턴이 10분 안에 3번째인가? ─ 아니면 끝
   │
   ├─ 안내가 꺼져 있음 ─────────────────────── SKIPPED_OFF
   ├─ 대기 중인 카드가 있거나 표시 후 15분 이내 ── SKIPPED_INTERVAL
   └─ 대기
        ├─ 앞뒤·좌우 가속도가 0.9m/s² 미만으로 3초 ─ 표시 ─ SHOWN 또는 FAILED
        ├─ 대기 중 안내를 끔 ──────────────────── SKIPPED_OFF
        └─ 60초 안에 잔잔한 순간이 없거나 주행 종료 ── SKIPPED_EXPIRED
```

`FAILED`는 간격을 시작하지 않습니다. 사용자가 보지 못한 카드 때문에 다음 카드를 막지 않기 위해서입니다. 표시 실패는 기록 저장을 막지 않습니다.

근거 유형: **연구**(논문·지침) / **실측**(우리가 측정) / **제품 판단**(근거 없음, 이유만 있음) / **구현 판단**(계산 안정성을 위한 값).

| 값 | 현재 | 유형 | 근거 |
| --- | --- | --- | --- |
| `repeatCount` 같은 패턴 반복 | 3번 | 제품 판단 | 한 번의 운행으로 단정하지 않는다는 최종 기획 §7을 따라 반복될 때만 권함. 3이라는 수의 연구 근거는 없음. 아래 측정에서 2번이면 카드 없는 주행이 22%, 4번이면 66% |
| `repeatWindowMs` 반복을 세는 범위 | 10분 | 제품 판단 | 최종 기획 §12의 10분당 정규화와 같은 단위. 연구 근거 없음 |
| `minIntervalMs` 카드 사이 최소 간격 | 15분 | 실측·제품 판단 | 아래 측정에서 20분 넘는 주행의 카드가 중앙값 1장, p90 2장. 피드백은 한두 번이 가장 효과적이고 더 많다고 나아지지 않았다는 Molloy 외(2023)와 방향이 같지만, 그 연구는 주행 후 주간 피드백이라 시간 규모가 다름 |
| `calmMps2` 잔잔함의 크기 | 0.9m/s² | 연구 | 사람 운전 가감속의 90%가 −0.89~0.96(Bosetti 외 2014). 평범한 움직임 범위 안일 때를 고름. 좌우 값은 추정치이고 조향이 없으면 앞뒤만 봄 |
| `calmForMs` 잔잔함의 지속 | 3초 | 제품 판단 | 차량 데이터로 말을 걸 시점을 고를 수 있다는 연구는 있으나(Semmens 외 2019, Kim 외 2018) 숫자를 주지 않음 |
| `expireAfterMs` 대기 만료 | 60초 | 제품 판단 | 한참 지난 움직임을 뒤늦게 전하지 않기 위함. 아래 측정에서 만료는 약 5%(555건, 표시 약 1만 건) |
| `accelerationWindowMs`, `minAccelerationSpanMs`, `maxGapMs` | 1초, 0.5초, 1초 | 구현 판단 | [탐지](detection-thresholds.md)와 같은 근사 |
| `CARD_LIFETIME_MS` 알림 제거 | 15초 | 실측·구현 판단 | 시스템이 카드를 약 9초 보여 줌(측정). 그 뒤 종 배지와 알림 센터에 지난 안내가 남지 않도록 제거. 약 15초에 활성 목록에서 제거, 그 뒤 화면에 카드와 배지 없음(측정) |

## 문구

어떤 문구를 띄울지는 주행에서 탐지한 패턴이 정합니다. 문구 자체는 패턴마다 고정입니다.

| 패턴 | 문구 | 출처 |
| --- | --- | --- |
| RAPID_START | 출발 후 몇 초 동안 천천히 속도를 높여보세요 | 최종 기획 §15 |
| HARD_STOP | 정지 지점보다 조금 일찍 감속해보세요 | 최종 기획 §15 |
| REPEATED_SPEED_CHANGE | 앞차와의 간격을 확보해 속도 변화를 줄여보세요 | 최종 기획 §15 |
| FAST_TURN | 커브에 진입하기 전에 미리 속도를 줄여보세요 | 최종 기획 §15 |
| REPEATED_SWAY | 핸들을 조금 더 부드럽게 돌려보세요 | 제품 판단. §15에 좌우 흔들림 조언이 없음 |

- **제목(모션케어)을 포함해 공백까지 30자 이내:** NHTSA 지침은 한 작업에서 30자(구두점 제외)를 넘는 글을 읽게 하는 기능을 주행 중 잠그도록 권고합니다. 미국의 자발적 지침이고 영어 기준이라 한글 30자가 같은 시간에 읽힌다는 뜻은 아닙니다. 그래도 지금 찾은 가장 구체적인 수치입니다. 에뮬레이터에서는 모두 한 줄에 표시됐습니다.
- **행동 하나를 권함:** 화면별 기능 분해 G02-F04가 카드 내용을 "행동 하나"로 정했고, 2026-11-04에 주행 담당이 데이터 기반 권장 문구로 확정했습니다. 효과를 연구로 확인한 문구가 아니라 팀 기획의 문구입니다.
- **주행 중 권장의 위험:** Xie 외(2026)는 실도로 안내에서 행동 지시 대신 정보 수준 피드백을 택했습니다. 지시가 운전자의 즉각적인 안전 판단과 충돌할 수 있다는 이유입니다. 최종 기획 §17도 운전 습관 조언은 출발 전과 운행 후를 중심으로 둡니다. 이 카드는 그와 다른 선택입니다. 명령형 대신 "~해보세요"로 쓰고 차가 잔잔할 때만 띄우지만, 그렇다고 위험이 없어지는 것은 아닙니다.
- **지금 상황을 판단한 문구가 아님:** 앞차와의 거리, 정지 지점, 커브 위치는 앱이 알지 못합니다. 반복 가감속은 교통 상황 때문일 수도 있습니다(최종 기획 §10.3). 문구는 반복된 패턴에 대한 일반적인 권장이고, 지금 앞차가 가깝다거나 커브가 다가온다는 뜻이 아닙니다.
- **멀미·위험·운전자·습관과 명령형을 쓰지 않음:** 진단이나 비난, 명령으로 읽히지 않게 한 제품 판단입니다. `GuidanceCopyTest`가 확인합니다.
- **탭 동작 없음:** 조작을 요구하지 않는다는 최종 기획 §17을 따릅니다. `distractionOptimized`를 선언하지 않아 주행 중에는 앱 화면이 가려지므로 눌러도 볼 화면이 없습니다.

처음 병합한 카드(PR #7)는 움직임만 전하는 관찰 문구였습니다. G02-F04를 확인하지 못한 판단이어서 같은 날 권장 문구로 바꾸고, 접수 초안([proposal.md](proposal.md))도 행동 하나를 권하는 내용으로 되돌렸습니다.

## 소리

카드가 뜨면 소리를 한 번 냅니다. 시작 화면의 "안내 소리"에서 알림음과 음성 중 고르고, "주행 중 안내"를 끄면 카드와 소리가 함께 꺼집니다. 소리는 부가 기능이라 재생하지 못해도 카드는 그대로 뜹니다.

```text
카드 표시 ─ 통화·내비 음성·음성 비서가 재생 중인가? ─ 예: 소리만 생략
   │
   ├─ 오디오 포커스 거부 ─────────────── 소리만 생략
   └─ 재생
        ├─ 포커스를 잃음 ─────────────── 즉시 멈춤
        ├─ 내비 음성 등이 새로 시작됨 ─── 즉시 멈춤
        ├─ 음성 실패 ──────────────────── 알림음으로 대체
        └─ 끝남 또는 15초 경과 ─────────── 포커스 반납
```

| 항목 | 현재 | 유형 | 근거 |
| --- | --- | --- | --- |
| 알림음과 음성을 운전자가 선택 | 기본은 알림음 | 제품 판단 | 2차 회의가 "음성은 별로일 것 같다"에서 알림음 방향으로 정리됐고 "운전자가 선택" 안도 나옴. 2026-11-05 주행 담당 결정 |
| 음성 엔진 | Pleos TextToSpeech SDK 3.3.1, `ON_DEVICE`, 한국어 | 문서·실측 | 온디바이스 모드는 앱 등록이 필요 없다고 문서에 적혀 있고, 에뮬레이터에서 등록과 인터넷 권한 없이 재생됨. 카드 문구 하나에 약 3초, 첫 재생은 약 4.5초 |
| 알림음의 앞 묵음 | 180ms | Pleos 문서 | 음성 안내 재생 앞에 150~200ms 묵음을 오디오 데이터에 넣도록 권장. 음성은 SDK가 재생해 앱에서 넣을 수 없음 |
| 알림음 | 784Hz→1047Hz 두 음, 0.46초 | 제품 판단 | 회의의 "또롱". 파일 없이 코드로 생성. 연구 근거 없음 |
| 오디오 용도 | `USAGE_NOTIFICATION` | 문서·제품 판단 | Pleos 표에서 NOTIFICATION 문맥. 내비·안전 용도로 위장하지 않음. SDK 기본값은 미디어(측정) |
| 포커스 | `GAIN_TRANSIENT_MAY_DUCK`, 재생 전 요청, 끝나면 반납 | Pleos 문서 | 오디오 포커스 가이드가 재생 전 요청과 공존 문맥의 `MAY_DUCK`을 요구. SDK는 포커스를 잡지 않음(측정) |
| 포커스를 잃으면 멈춤 | 모든 손실 | 실측·Pleos 문서 | 다른 앱이 독점 포커스를 가져가도 TTS는 끝까지 재생됨(측정). 가이드는 Gleo 음성 명령 중 즉시 멈춤을 요구 |
| 통화·내비 음성·음성 비서와 겹치지 않음 | 시작 전 확인, 재생 중 감시 | 실측·제품 판단 | 내비 음성이나 통화 포커스가 있어도 포커스가 허용되고 내비 음성과 함께 재생됨(측정). 포커스만으로 막히지 않아 앱에서 확인. 턴 안내를 가리면 안 된다는 제품 판단 |
| 재생 시간 제한 | 15초 | 구현 판단 | 서비스가 끝을 알리지 않아도 포커스를 돌려주기 위함 |
| 음성 실패 시 | 알림음 | 구현 판단 | 선택지 도감의 "TTS 불가 시 대체" 방침. 사전 녹음 대신 이미 있는 알림음을 씀 |

- **음성과 알림음의 효과:** Larsson·Niemand(2015)의 시뮬레이터 실험(14명, 메뉴 탐색)에서 압축 음성은 시선 횟수와 시간을 줄였고, 음악적 알림음은 줄이지 못했습니다. 메뉴 탐색 실험이고 압축 음성이라 우리 카드에 그대로 옮기지 않습니다. 우리 소리가 시선을 줄이는지는 시험하지 않았습니다.
- **재생 결과는 저장하지 않음:** `SHOWN`은 카드 기준입니다. 소리의 시작·생략·멈춤은 logcat의 `GuidanceSound` 태그에만 남습니다.
- **SDK 일부를 뺌:** 서버 모드 로그인용 `universal-access`를 의존성에서 제외했습니다. 온디바이스 모드는 이 라이브러리 없이 동작했고(측정), 빼면 Material·네이티브 라이브러리가 들어오지 않아 시험 앱 APK가 25MB에서 5.3MB로 줄고 16KB 정렬 lint 오류도 사라집니다. 서버 모드를 쓰려면 다시 넣어야 합니다.
- **인터넷 권한 제거:** SDK가 추가하는 `INTERNET`을 Manifest에서 지웠습니다. 온디바이스 모드는 권한 없이 재생됐습니다(측정).

## 기록

`TripSnapshot.guidance`에 `GuidanceEvent`로 저장합니다. 샘플과 같은 트랜잭션입니다. `guidance_events` 테이블에는 일부러 기본 키를 두지 않았습니다. 기록용 값이 겹쳤다고 주행 저장이 실패하면 안 되기 때문입니다.

| 결과 | 뜻 |
| --- | --- |
| SHOWN | 시스템에 알림을 보냄. 사용자가 봤다는 뜻은 아님 |
| SKIPPED_INTERVAL | 대기 중이거나 최소 간격 이내 |
| SKIPPED_OFF | 안내가 꺼져 있음 |
| SKIPPED_EXPIRED | 60초 안에 잔잔한 순간이 없거나 그 전에 주행이 끝남 |
| FAILED | 알림이 꺼져 있거나 권한이 없거나 표시 중 예외 |

`observedMs`는 카드가 결정된 시각, `elapsedMs`는 결과가 정해진 시각입니다. 잔잔한 순간을 기다린 시간은 두 값의 차이이므로 보류를 별도 행으로 두지 않습니다.

## 빈도 측정

공개 주행 자료 VED에 같은 규칙을 적용했습니다. 17,245개 주행, 3,255시간입니다. `measure_guidance.py`로 재현합니다.

```sh
python3 -I docs/detection-limits/measure_guidance.py <VED_*_week.csv 폴더> <결과.json>
```

| 규칙 | 10분당 카드 | 카드 간격(분) | 카드 없는 주행 | 20분 넘는 주행의 카드 수(중앙값 / p90 / 최대) |
| --- | --- | --- | --- | --- |
| **3번, 15분 간격 (현재)** | **0.51** | **19.5** | **45.2%** | **1 / 2 / 5** |
| 3번, 5분 간격 | 0.64 | 15.6 | 45.2% | 2 / 3 / 8 |
| 3번, 10분 간격 | 0.54 | 18.4 | 45.2% | 1 / 2 / 6 |
| 3번, 20분 간격 | 0.50 | 20.1 | 45.2% | 1 / 2 / 4 |
| 2번, 15분 간격 | 0.75 | 13.4 | 22.2% | 2 / 2 / 6 |
| 4번, 15분 간격 | 0.31 | 32.3 | 66.4% | 1 / 2 / 4 |
| 반복 패턴만 바로, 15분 간격 | 0.76 | 13.2 | 21.7% | 2 / 2 / 6 |
| 모든 패턴 바로, 15분 간격 | 0.97 | 10.4 | 4.4% | 2 / 3 / 8 |

- **한계:** VED에는 조향이 없어 앞뒤 패턴만 셉니다. 미국 앤아버 주행이고, [탐지 문서](detection-thresholds.md#실측)에 적은 대로 빠른 출발이 과대 집계되는 자료라 실제 값은 달라질 수 있습니다.
- **읽는 법:** 긴 주행에서 한두 장에 그치는 것을 확인한 값입니다. 사용자가 몇 장을 원하는지는 말해 주지 않습니다.

## 쓰지 않은 방법

| 방법 | 이유 |
| --- | --- |

## 확인하지 못한 것

- 실차 신호에서 카드가 뜨는 빈도와 시점
- App Market의 `CATEGORY_MESSAGE` 사용 승인
- 실차 스피커의 음량과 음질. 음성은 2026-11-05에 주행 담당이 에뮬레이터 출력(노트북 스피커)을 듣고 잘 나오는 것을 확인했고, 앱에서 재생한 알림음은 듣고 확인하지 않음
- 음악이 실제로 줄어드는지. `MAY_DUCK`을 요청해도 음악을 재생하는 앱에 포커스 변화가 전달되지 않았음
- 실제 통화 중의 동작. 통화 포커스로만 시험했고 `AudioManager.mode` 분기는 에뮬레이터에서 재현하지 못함
- App Market의 `TTS_SERVICE` 승인. My Project의 TextToSpeech SDK 접근은 문서상 "Coming Soon"임
- 음성으로 듣는 것이 운전 부담이나 멀미에 미치는 영향
- 경로 안내 화면을 가리는지. 에뮬레이터 내비에 경로가 표시되지 않음
- 권장 문구를 주행 중 보여 주는 것의 안전성, 문구대로 운전이 바뀌는지, 동승자에게 주는 효과, 어린이 동승 상황, 한국 주행 자료
- 알림을 허용하지 않은 경우의 대안. 지금은 `FAILED`로만 기록하며, 기획의 앱 안 배너와 알림 센터 대안은 App Market 답을 받은 뒤 정합니다.
