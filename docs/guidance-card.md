# 주행 중 안내 카드의 근거

`GuidanceLimits`의 값과 `guidanceCopy`의 문구마다 출처와 확인 수준을 적습니다. 값을 바꾸면 이 문서와 [`detection-limits/measure_guidance.py`](detection-limits/measure_guidance.py)의 `Rule`을 함께 고칩니다.

## 먼저 알아 둘 점

- **규칙 값 대부분은 제품 판단입니다.** 주행 중 안내를 몇 번 반복됐을 때 몇 분 간격으로 띄워야 하는지 직접 답하는 연구를 찾지 못했습니다. 표에 유형을 나눠 적습니다.
- **카드는 차의 움직임만 전합니다.** 동승자의 증상이나 멀미 여부를 판단하지 않습니다. 카드가 멀미를 줄이는지는 검증하지 않았습니다.
- **정차 중이 안전하다고 주장하지 않습니다.** NHTSA 지침은 신호 대기처럼 멈춘 상황도 P 기어가 아니면 주행으로 봅니다. 잔잔한 순간을 기다리는 규칙은 차가 흔들리는 중에 카드를 띄우지 않으려는 것이고, 카드를 보는 부담이 없다는 뜻이 아닙니다.

## 규칙

```text
패턴 관찰 ─ 같은 패턴이 10분 안에 3번째인가? ─ 아니면 끝
   │
   ├─ 안내가 꺼져 있음 ─────────────────────── SKIPPED_OFF
   ├─ 대기 중인 카드가 있거나 표시 후 15분 이내 ── SKIPPED_INTERVAL
   └─ 대기
        ├─ 앞뒤·좌우 가속도가 0.9m/s² 미만으로 3초 ─ 표시 ─ SHOWN 또는 FAILED
        ├─ 대기 중 안내를 끔 ──────────────────── SKIPPED_OFF
        └─ 60초 안에 잔잔한 순간이 없거나 주행 종료 ── SKIPPED_EXPIRED
```

`FAILED`는 간격을 시작하지 않습니다. 사용자가 보지 못한 카드 때문에 다음 카드를 막지 않기 위해서입니다. 표시 실패는 기록 저장을 막지 않습니다.

근거 유형: **연구**(논문·지침) / **실측**(우리가 측정) / **제품 판단**(근거 없음, 이유만 있음) / **구현 판단**(계산 안정성을 위한 값).

| 값 | 현재 | 유형 | 근거 |
| --- | --- | --- | --- |
| `repeatCount` 같은 패턴 반복 | 3번 | 제품 판단 | 한 번의 운행으로 단정하지 않고 "반복되고 있어요"로 표현한다는 최종 기획 §7을 따름. 3이라는 수의 연구 근거는 없음. 아래 측정에서 2번이면 카드 없는 주행이 22%, 4번이면 66% |
| `repeatWindowMs` 반복을 세는 범위 | 10분 | 제품 판단 | 최종 기획 §12의 10분당 정규화와 같은 단위. 연구 근거 없음 |
| `minIntervalMs` 카드 사이 최소 간격 | 15분 | 실측·제품 판단 | 아래 측정에서 20분 넘는 주행의 카드가 중앙값 1장, p90 2장. 피드백은 한두 번이 가장 효과적이고 더 많다고 나아지지 않았다는 Molloy 외(2023)와 방향이 같지만, 그 연구는 주행 후 주간 피드백이라 시간 규모가 다름 |
| `calmMps2` 잔잔함의 크기 | 0.9m/s² | 연구 | 사람 운전 가감속의 90%가 −0.89~0.96(Bosetti 외 2014). 평범한 움직임 범위 안일 때를 고름. 좌우 값은 추정치이고 조향이 없으면 앞뒤만 봄 |
| `calmForMs` 잔잔함의 지속 | 3초 | 제품 판단 | 차량 데이터로 말을 걸 시점을 고를 수 있다는 연구는 있으나(Semmens 외 2019, Kim 외 2018) 숫자를 주지 않음 |
| `expireAfterMs` 대기 만료 | 60초 | 제품 판단 | 한참 지난 움직임을 뒤늦게 전하지 않기 위함. 아래 측정에서 만료는 약 5%(555건, 표시 약 1만 건) |
| `accelerationWindowMs`, `minAccelerationSpanMs`, `maxGapMs` | 1초, 0.5초, 1초 | 구현 판단 | [탐지](detection-thresholds.md)와 같은 근사 |
| `CARD_LIFETIME_MS` 알림 제거 | 15초 | 실측·구현 판단 | 시스템이 카드를 약 9초 보여 줌(측정). 그 뒤 종 배지와 알림 센터에 지난 안내가 남지 않도록 제거. 약 15초에 활성 목록에서 제거, 그 뒤 화면에 카드와 배지 없음(측정) |

## 문구

| 패턴 | 문구 |
| --- | --- |
| RAPID_START | 출발 직후 속도 변화가 반복되고 있어요 |
| HARD_STOP | 정차 직전 속도 변화가 반복되고 있어요 |
| REPEATED_SPEED_CHANGE | 가속과 감속이 반복되고 있어요 |
| FAST_TURN | 회전 구간의 좌우 움직임이 반복되고 있어요 |
| REPEATED_SWAY | 좌우 움직임이 반복되고 있어요 |

- **제목(모션케어)을 포함해 공백까지 30자 이내:** NHTSA 지침은 한 작업에서 30자(구두점 제외)를 넘는 글을 읽게 하는 기능을 주행 중 잠그도록 권고합니다. 미국의 자발적 지침이고 영어 기준이라 한글 30자가 같은 시간에 읽힌다는 뜻은 아닙니다. 그래도 지금 찾은 가장 구체적인 수치입니다. 에뮬레이터에서는 모두 한 줄에 표시됐습니다.
- **행동을 지시하지 않고 관찰만 전함:** Xie 외(2026)는 실도로 안내에서 행동 지시 대신 정보 수준 피드백을 택했습니다. 지시가 운전자의 즉각적인 안전 판단과 충돌할 수 있다는 이유입니다. 최종 기획 §15도 행동 조언은 시동 시에 주고, §17도 운전 습관 조언은 출발 전과 운행 후를 중심으로 합니다.
- **멀미·위험·운전자·습관이라는 단어를 쓰지 않음:** 진단이나 비난으로 읽히지 않게 한 제품 판단입니다. `GuidanceCopyTest`가 확인합니다.
- **탭 동작 없음:** 조작을 요구하지 않는다는 최종 기획 §17을 따릅니다. `distractionOptimized`를 선언하지 않아 주행 중에는 앱 화면이 가려지므로 눌러도 볼 화면이 없습니다.

주행 중 카드를 관찰 문구로 두는 것은 2026-11-04에 주행 담당이 확정했고, 접수 초안([proposal.md](proposal.md))도 같은 내용으로 고쳤습니다. 이전 표현은 "행동 하나를 잠깐 보여 주고"였습니다.

## 기록

`TripSnapshot.guidance`에 `GuidanceEvent`로 저장합니다. 샘플과 같은 트랜잭션입니다. `guidance_events` 테이블에는 일부러 기본 키를 두지 않았습니다. 기록용 값이 겹쳤다고 주행 저장이 실패하면 안 되기 때문입니다.

| 결과 | 뜻 |
| --- | --- |
| SHOWN | 시스템에 알림을 보냄. 사용자가 봤다는 뜻은 아님 |
| SKIPPED_INTERVAL | 대기 중이거나 최소 간격 이내 |
| SKIPPED_OFF | 안내가 꺼져 있음 |
| SKIPPED_EXPIRED | 60초 안에 잔잔한 순간이 없거나 그 전에 주행이 끝남 |
| FAILED | 알림이 꺼져 있거나 권한이 없거나 표시 중 예외 |

`observedMs`는 카드가 결정된 시각, `elapsedMs`는 결과가 정해진 시각입니다. 잔잔한 순간을 기다린 시간은 두 값의 차이이므로 보류를 별도 행으로 두지 않습니다.

## 빈도 측정

공개 주행 자료 VED에 같은 규칙을 적용했습니다. 17,245개 주행, 3,255시간입니다. `measure_guidance.py`로 재현합니다.

```sh
python3 -I docs/detection-limits/measure_guidance.py <VED_*_week.csv 폴더> <결과.json>
```

| 규칙 | 10분당 카드 | 카드 간격(분) | 카드 없는 주행 | 20분 넘는 주행의 카드 수(중앙값 / p90 / 최대) |
| --- | --- | --- | --- | --- |
| **3번, 15분 간격 (현재)** | **0.51** | **19.5** | **45.2%** | **1 / 2 / 5** |
| 3번, 5분 간격 | 0.64 | 15.6 | 45.2% | 2 / 3 / 8 |
| 3번, 10분 간격 | 0.54 | 18.4 | 45.2% | 1 / 2 / 6 |
| 3번, 20분 간격 | 0.50 | 20.1 | 45.2% | 1 / 2 / 4 |
| 2번, 15분 간격 | 0.75 | 13.4 | 22.2% | 2 / 2 / 6 |
| 4번, 15분 간격 | 0.31 | 32.3 | 66.4% | 1 / 2 / 4 |
| 반복 패턴만 바로, 15분 간격 | 0.76 | 13.2 | 21.7% | 2 / 2 / 6 |

- **한계:** VED에는 조향이 없어 앞뒤 패턴만 셉니다. 미국 앤아버 주행이고, [탐지 문서](detection-thresholds.md#실측)에 적은 대로 빠른 출발이 과대 집계되는 자료라 실제 값은 달라질 수 있습니다.
- **읽는 법:** 긴 주행에서 한두 장에 그치는 것을 확인한 값입니다. 사용자가 몇 장을 원하는지는 말해 주지 않습니다.

## 쓰지 않은 방법

| 방법 | 이유 |
| --- | --- |
| 패턴을 찾을 때마다 바로 표시 | 15분 간격을 둬도 10.4분에 한 장이고 카드 없는 주행이 4.4%뿐. 탐지 기록과 안내 빈도는 별개 |
| 정차할 때만 표시 | 정차가 안전한 순간이라는 근거가 없음(NHTSA). 정차가 드문 고속 주행에서는 카드가 나오지 않음 |
| 오버레이로 내비 위에 직접 그리기 | 일반 사용자가 권한을 줄 설정 화면이 없음(측정). P12 작업 카드도 우회를 금지 |
| 일반 알림 | 내비 위에 뜨지 않음(측정) |
| 행동 지시 문구 | 위 문구 절 참고 |

## 확인하지 못한 것

- 실차 신호에서 카드가 뜨는 빈도와 시점
- App Market의 `CATEGORY_MESSAGE` 사용 승인
- 소리. 채널 중요도를 높게 두었으나 실제 소리가 나는지 확인하지 못함
- 경로 안내 화면을 가리는지. 에뮬레이터 내비에 경로가 표시되지 않음
- 카드가 동승자나 운전자에게 주는 효과, 어린이 동승 상황, 한국 주행 자료
- 알림을 허용하지 않은 경우의 대안. 지금은 `FAILED`로만 기록하며, 기획의 앱 안 배너와 알림 센터 대안은 App Market 답을 받은 뒤 정합니다.
